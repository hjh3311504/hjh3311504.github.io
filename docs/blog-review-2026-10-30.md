## 사실 확인과 재현 자료

- 로컬 QR 도구에서 공개 블로그 주소와 제목 `모임🎉`를 입력했다. 미지원 글자 안내와 SVG 저장 비활성, PNG 저장 가능 상태를 확인하고 실제 화면을 촬영했다.
- 저장한 PNG는1024×952다. jsQR로 읽은 주소가 입력한 `https://hjh3311504.github.io/blog`와 일치했다. 파일을 직접 열어 제목과 이모지를 확인했다. 실제 카메라·종이 스캔은 하지 않았다.
- 주소는 유지하고 제목만 `모임 안내`로 바꿔 SVG를 저장했다. 제목 영역이 `<text>`가 아닌 도형이며 외부 글꼴 참조가 없음을 확인했다.
- Chromium의 iPhone13 기기 설정으로 PNG 저장 창·생성 이미지·‘파일 다운로드’ 링크를 확인했다. 실제 iPhone이나 모바일 Safari의 확인 결과로 보지 않는다.
- 입력·환경·판독 결과는 `static/downloads/blog/qr-title/verification.json`, 재현 코드는 `scripts/capture_blog_qr_title.js`에 있다. Chromium151.0.7922.34·macOS에서 확인했다. 타사 요청은 차단했다.
- 초기 재현은 준비 중인 그림을 참조한 초안 때문에 페이지500, 필수 표시가 붙은 입력 라벨의 완전 일치 때문에 실패했다. 초안을 잠시 옮기고 라벨 선택과 페이지 응답 확인을 고친 뒤 재현을 완료했다. 제품 코드는 바꾸지 않았다.
- SVG 제목 생성·SUIT 글자 지원 검사·PNG의 시스템 글꼴 보완·휴대폰 저장 창·재시도 안내는 현재 코드를 대조했다. SVG path와 fontkit의 글자 지원 검사 공식 원문을 확인했다.
- 기존 QR 소개 FAQ는 제한을 한 줄로 안내한다. 이번 글은 구체적 실패 안내, PNG 보존과 SVG 복구, 편집 가능한 제목과 도형의 차이를 다룬다. 기존 인식·주소 길이 글과 해결 대상이 다르다.
- 자체 화면과 저장 예제, SUIT OFL·시스템 이모지 권리의 구분을 `THIRD_PARTY_NOTICES.md`에 추가했다. 기능·광고·개인정보 설정은 바꾸지 않았다.

## Opus 리뷰와 반영

현재 `orca-cli` 안내를 읽고 `orca agent launch --agent claude --model claude-opus-5-5`로 읽기 전용 리뷰를 실행했다. Orca 세션은 `claude_8ebeab78_859b_45d8_9ccb_07a5e1837989`, Claude 세션은 `6c08ba21-cad3-47eb-8621-802be1366d30`이다. 요청 모델과 실제 리뷰 응답의 `message.model`이 모두 **`claude-opus-5-5`**였다. 별도 제목 생성 응답은 리뷰로 세지 않았다.

본문·그림·실제 저장 파일·확인 JSON·재현 방법·현재 코드·기존 글·출처를 전달했다. 최종 판정은 ‘중요3건을 고치면 게시 가능’이었다. 리뷰 담당자는 저장소 파일을 수정하지 않았다.

- 중요1: 휴대폰·태블릿의 실제 버튼 이름 ‘파일 다운로드’와 조건부 ‘공유하기’를 적었다.
- 중요2: 재시도 오류의 원인에 글자 도형 생성 실패를 포함했다. 실패가 계속되면 입력을 메모한 뒤 새로고침하고, 급하면 PNG로 저장하도록 안내했다.
- 중요3: 이모지 외의 미지원 글자·전각 공백도 설명했다. 실제 SUIT에서 `é`·`漢`·전각 공백은 미지원, `★`·`♥`는 지원임을 직접 확인하고 재현 코드와 JSON에 추가했다.
- 선택 개선: 독자의 기존 주소를 유지하게 했고, 미지원 글자의 ‘재시도’를 ‘같은 제목을 다시 입력’으로 고쳤다. PNG 크기·모바일 확인 범위·Apple Color Emoji 고지·기존 확장자 글 링크도 보완했다.
- 리뷰 담당자는 저장 SVG를 이미지로 바꿔 같은 주소가 읽히는 것도 확인했다. 소개 FAQ보다 구체적인 실패·복구·저장 구조를 다뤄 별도 글로 둘 수 있다고 판단했다.
