# 결승 입구를 막는 회전판

- 날짜: 2026-09-17
- 상태: 적용
- 연결: [REQ-MR-002](../requirements/marble-race.yaml), [화면](../design/screens/SCR-WEB-004.md)

## 변경 이유

사용자가 제공한 결승 참고 이미지에는 직선 깔때기와 좁은 통로가 있다. 회전판의 중심은 출구 왼쪽에 있고 판 끝이 입구를 가로막는다. 기존 구현은 넓은 깔때기 가운데에 회전판을 두고 하단 벽을 곡선으로 만들었으므로 요청한 구조와 달랐다.

## 결정

- 양쪽 직선 벽은 결승 시작점400아래에서 동시에 중앙 폭40통로로 연결한다. 벽 두께12는 통로 바깥으로 둔다. 둥근 끝을 겹쳐 연결부에 틈이 생기지 않게 한다.
- 회전판 중심은 `(290, 결승 시작점+400)`이다. 중앙 통로 중심보다70왼쪽이다. 길이180·두께16·둥근 끝과4.8초 회전 주기는 유지한다.
- 판은 시계 방향으로 회전한다. 이 방향에서는 입구를 지나는 판 끝이 구슬을 아래로 밀어낸다. 반대 방향은 입구에 쌓인 구슬을 반복해서 위로 밀어 올려 체류 시간이 길어졌다. 시작 각도만 경기 난수로 정한다.
- 결승 벽의 마찰은0이다. 직선 깔때기와 좁은 입구에서 반복 접촉할 때 아래로 미끄러지는 속도가 계속 줄어드는 현상을 피한다. 회전판의 반발계수0.35·마찰0.05와 실제 표면 속도에 따른 충돌은 유지한다.
- 흰색 벽 앞에 청록색 판을 그린다. 미니맵은 별도 약식 깔때기 대신 실제 벽·회전판 데이터를 사용한다. 카메라도 새 회전축 위치를 기준으로 확대 범위를 계산한다.
- 결승 판정선은 시작점470아래다. 실제 아래 방향 교차·당첨 방식·0.5배속 연출·충돌음은 유지한다. 충돌 생략, 정체 바람, 순간이동은 추가하지 않는다.

## 검증

첫 직선 배치에서 회전 방향을 모두 사용했을 때90경기는 완주했으나 결승 최대 체류가44.18초였다. 시계 방향으로 바꾼 뒤 최대17.22초였고8경기가15초 목표를 넘었다. 벽 마찰을0으로 조정한 뒤 같은8개 조건의 최대 체류는14.29초 미만으로 줄었다. 아래 최종 검사는 이 조정이 적용된 배치를 기준으로 한다.

최종 연결부는 둥근 벽 끝을 반두께만큼 연장해 그림과 충돌 면이 끊기지 않도록 했다. 이 변경까지 포함한 결과는 [측정 기록](../marble-race-finale-measurements.json)에 남긴다.

- 기본3개 맵×2/30/60개×난수10개, 총90경기 전원 완주. 전체 경기 최대60.42초.
- 결승 체류15초 목표는14/90경기에서 초과했다. 최대17.95초이며 모두60개 경기다. 목표 검사는 실패로 유지한다. 제한을 늘리거나 충돌을 생략하지 않았다.
- 결승 진입 차이가1초 이하인75경기 중25경기에서 진입 선두가 우승하지 못했다(33.3%).
- 일반·특수 물리, Worker, 오디오, 카메라 등 단위 검사81개 중80개 통과. 실패1개는 위 결승15초 목표 검사다. 직선 벽 연결·입구 개폐·시작 각도별60개 밀집 통과·중복 골인 방지 검사는 통과했다.
- 데스크톱과 모바일에서 결승 배치를 확인했다. 화면 크기가 바뀌면 일시정지·종료 상태에서도 확대 비율과 결승 화면 위치를 즉시 갱신한다. 기존에는 경기 시간이 멈춘 상태에서 이전 화면 크기의 비율이 남아 결승선이 잘릴 수 있었다.
- 관련 Playwright 검사에서 첫 충돌·결승 충돌음, 아래 방향 카메라, 화면 크기 변경과 전체화면을 확인했다(최종 build에서2개 통과). 첫 시도에서는 음원 준비를 포함한6초 대기에서 시간 초과가 발생했으며 검사 제한을 바꾸지 않고 재검사했다. 첫 번째·마지막·n번째 당첨 표시는 앞선 build의 관련 검사에서 통과했다.
- lint·Svelte 정적 검사·build·정적 페이지 검증·UI 문서 연결 검증·`git diff --check` 통과.
- 최종 배치의 키보드 맵·난수47·1,000개 검사는 1,000개 전원 완주했다. 경기 시간122.68초, 최대 결승 체류82.68초다. 1,000개 관측 한도600초 안에 완주했으며 단일 통로의 대기 시간은60개 이하15초 목표와 구분한다.
