# 200개 이상 경기는 출발부터 이동 분할 상한8을 사용한다

- 날짜:2026-09-26
- 상태: 채택
- 승인: 기존 난수의 경로·당첨 결과가 달라질 수 있다는 설명 뒤 사용자가 “적용해”로 승인했다.
- 관련: [그림 수정 뒤 로컬 결승과 원격 성능](2026-09-26-그림-수정-후-로컬-결승과-원격-성능.md), REQ-MARBLE-004

## 결정

200개 이상 경기에서는 결승 진입 여부와 관계없이 내부 이동 분할의 거리 상한8을 사용한다.199개 이하는4를 유지한다. 실제 구슬 반지름13보다 작으며 빠른 이동은 속도에 따라 계속 더 나눈다. 기본 물리 간격1/120초, 지형·회전바·반발계수·스킬 규칙·강제0.25배속은 유지한다. 경기 시간을 버리지 않는다.

예전에는1000개 경기의 출발·일반 밀집 상태를 과거 해시와 비교했다. 승인된 이동 분할 변경은 경로를 바꾸므로 이 비교의 의미도 바뀐다. 기대 해시를 새 출력으로 덮어쓰지 않고, 같은 환경에서 매 단계 캐시를 새로 만드는 계산과720단계의 구슬·블록·스킬·이벤트·도착 순서를 정확히 비교한다. 기존 결승 검사와 같은 방식으로 출발·일반 밀집까지 범위를 넓힌다.1000개 출발10경기초의 모든 효과음·스킬 이벤트와 상태를0.25·1·2배속에서 비교하는 검사를 추가한다.

## 적용 후 비교

같은 장비에서 변경 전과 변경 후1000개·도각도각 키보드·난수47·스킬ON의 출발10경기초를 번갈아3회 계산했다.

| 반복 | 변경 전   | 변경 후   |
| ---- | --------- | --------- |
| 1    | 1790.67ms | 1239.69ms |
| 2    | 1555.80ms | 1046.69ms |
| 3    | 1548.59ms | 1155.96ms |

평균1631.69ms에서1147.45ms로 약30% 줄었다. 이 값은 물리 계산 비용이며 브라우저의 실제 배속·fps와 구분한다. 원본은 `.context/travel8-applied/compare.log`다.

## 검증

- marble-race 단위 검사254개 중253개가 첫 실행에 통과했다. 새 분할 횟수 검사의 기대값을 잘못 계산한1개는 수정 후 재실행해 통과했다. 속도0의 기본값에서199개는2분할,200개 이상은1분할이며 중력의 이동 거리로 검증한다.
- 1000개 밀집의 실제 겹침은 최대0.49998, 보간 겹침은 최대0.50000 미만이었다.4·8·32물리 단계 간격의 표시를 확인했다.
- 1000개·회전각4가지·35경기초의 벽 통과 방지와 중앙 입구를 거친 골인이 통과했다. 출발·결승에서 빠르게 움직이는 구슬과 얇은 벽도 검사했다.
- 번개 고정 구슬의 회전바 밀림, 얼음 고정, 상태 전송·Worker·효과음·스킬 검사와 강제0.25배속 검사를 통과했다.
- 1000개 출발과200개 결승의0.25·1·2배속 재현성이 통과했다. 출발·일반 밀집·결승의 캐시 유무에 따른720단계 비교도 통과했다.
- 수정한 물리 최적화 검사 파일8개 항목은 최종 재실행에서 모두 통과했다. 다른 도구의 전체 단위 테스트는 로컬에서 실행하지 않았다.
- 최종 build1회와 정적 결과 검증을 완료했다. 관련 성능·시간 보존·화면·스킬·효과음 브라우저 검사30개가 통과했다. 접근성 snapshot 뒤390px·1440px 화면을 확인했다.
- 로컬 출발·진행2배속은 데스크톱2.005·1.998배와 약60fps, 모바일 CPU4배 감속2.007·2.007배와50.1·59.5fps였다. 모바일 표본 일부는 단위 검사와 실행 시간이 겹쳤으므로 단독 실행과의 정밀 비교 수치로 사용하지 않는다.
- 정적 검사 오류·경고0개, 변경 코드 ESLint·Prettier·`git diff --check`, 전체 화면 연결 검사를 통과했다. 변경한 REQ-MARBLE-002/004 validator는 오류0개와 기존 긴 문장 경고2개였다. 전체 요구사항 validator는 변경하지 않은 REQ-MARBLE-005의 기존 `behavior` 분류를 지원하지 않아 실패했다. 해당 실패를 전체 검증 통과로 보고하지 않는다.
