# 구슬 레이스 화면·경기 길이·음향 개선

- 상태: 구현 및 검증, 시간·완주 목표의 미달 항목은 아래에 구분한다.
- 승인: 사용자가 화면·경기 길이·음향 개선 계획의 구현을 요청했다. 별도 시안 승인을 의미하지 않는다.
- 연결: REQ-MARBLE-001~004, SCR-WEB-004.

## 결정

설정 문구·맵 카드·도감·도착 순위를 정리한다. 맵 카드에서는 설명을 빼고 선택한 맵의 설명을 목록 아래에 둔다. 종료 뒤 다른 맵을 고르거나 선택된 커스텀 맵을 수정·삭제하면 결과·축하 효과·카메라를 정리하고 준비 화면으로 돌아간다. 설정과 저장 형식은 보존한다.

일반4구역·20열의 줄 수는 `max(4, round(12 × √(전체 구슬 수 / 30)))`로 정한다. 참가자 곱하기를 펼친 전체 수만 사용한다. 특수 구간 높이1220·3초 복구·블록 크기·교차 배치는 유지한다.30명은 기존960개다.2/10/60/100명은320/560/1360/1760개다. 준비 화면에서도 실제 배치 높이를 사용하되 표시할 구슬과 타일만 만든다. 매우 큰 명단을 미리보기 위해 모든 블록을 한꺼번에 만들지 않는다. 전체 보기에서 한 타일이 화면 약3px보다 작으면 재질 구역으로 요약한다.

크랙 왁스는 크기와 위치를 유지하며 좌측·중앙은 오른쪽 아래30도, 우측은 왼쪽 아래30도로 기울인다. 충돌·압축·복구 겹침·복구 윤곽도 같은 각도를 사용한다. 특수 블록 도감과 경기장 그림을 같은 함수로 그린다.

미니맵은 데스크톱100×300px·모바일64×220px로 키운다. 마우스·터치·키보드 탐색 동안만 자동 카메라를 대신하며 이탈·해제·Escape·포커스 이탈 시 현재 후보로 부드럽게 돌아간다. 물리·당첨·결승0.25배속은 독립적으로 유지한다. 탐색 화면과 음향·흰색 표시 상자의 범위를 맞춘다.

도착 순위는 최소200px·최대3열의 카드다. 보이는 행과 여유 행만 렌더링하고 검색·열 변경·초기화 때 스크롤을 보정한다. 카드 선택은 추적, 결과 복사는 전체 구슬을 대상으로 한다.

전체 동시 재생을3개에서6개로 늘리고 도각1을 포함한 일반 재질은 각각3개로 명시한다. 이전 설정값6개·12개가 전체 한도 확대와 함께 풀리지 않게 했다. 크랙 왁스3개·얼음 경사판/고무 범퍼/팡파레1개와 기존 그룹 제한·간격·음량·음원은 유지한다. 팡파레 교체 때도 짧은 감쇠가 끝난 뒤 새 소리를 시작해 순간적으로6개를 넘지 않는다.

## 경기 시간 측정

환경은 macOS26.6.2, Apple M5(arm64), Node24.11.0이다. `node scripts/measure_marble_balance.js`로3개 맵×2/10/20/30/60/100개×난수1~10의180경기를 실행했다. 실제 충돌을 모두 계산하고 같은 경기를 첫번째·여러명3명(2명 경기는2명)·n번째(올림한 중간 순번)·마지막 방식으로 관측했다.

다음은 **계산상 재생 시간 중앙값**이다.1배속과 결승0.25배속을 합산했다. 물리 계산 시간을 배속으로 나눈 값이며 브라우저 프레임 지연·로딩·정지는 포함하지 않는다. 실제 브라우저 소요 시간의180경기 검증을 대신하지 않는다.

기존 단위 검사의 결승15초 목표도 미달이다. 변경 배치의2/30/60개×3개 맵×난수10개에서는 전원120경기초 안에 완주했으나59/90경기가 결승 체류15초를 초과했다. 전체 최대99.63초, 결승 최대52.56초다. 변경 전에도 해당 목표는55/90경기에서 실패했다. 별도60개 결승 밀집 검사도 제한 시간 안에40개 도착으로 계속 실패한다. 이번 변경으로 결승 밀집 문제가 해결됐다고 표시하지 않는다.

## 화면·음향 검증

- 인원별 줄 수·배치 높이, 준비 화면의 실제 인원 적용, 기울어진 왁스의 충돌·압축·복구 대기를 단위 검사한다.
- 같은 재질4번째 차단, 전체6개 허용·7번째 차단, 일반3개와 장치 동시 재생, 기존 장치1개·28ms 제한·팡파레 교체·정리를 검사한다. 실제 사람이 새 겹침 결과를 청음한 것은 아니다.
- Chromium에서 명단 도움말·간결한 맵 카드·도감 실제 그림, 맵 선택·수정·삭제 뒤 초기화, 미니맵 호버·키보드·터치 이동/해제/취소, 일시정지·결승·전체화면, 밝은/어두운 화면을 검사했다.
- 1,000개 순위 카드의 부분 렌더링·검색·추적·반응형 열 변경·전체 결과 복사를 검사했다. 종료·결승 화면 검사는 실제 Worker 준비 후 재현 가능한 상태를 주입한다. 해당 화면 검사를 물리 완주 검증으로 간주하지 않는다.

## 대규모 경기와 화면 성능

`node scripts/measure_marble_balance.js --large`로 각 맵300개·1,000개를 난수1에서 관측했다.6경기 모두600경기초 이내 전원 도착했다. 많은 난수의 완주를 보장하는 결과는 아니다.

Chromium151에서 실제1,000개 Worker 경기의 첫5초 화면을 측정했다. 물리 모의 응답 없이 실행했고 음원 로딩을 제외하려고 음소거했다. 화면 갱신106.46fps, 일시정지 버튼 반응4.6ms로30fps·200ms 목표를 충족했다. 화면 갱신 횟수는 Worker가 보낸 새 물리 상태 횟수와 다르다. 모바일·다른 장치의 성능이나 경기 내내 같은 성능을 보장하지 않는다. 백만 개 준비 취소와 명단 보존도 통과했다.

## 검사 결과

`npm test`는 Team Maker49개·QR11개·구슬 레이스114개가 통과했다. 구슬 레이스의 기존 결승 체류시간·밀집 완주 목표2개는 위에 기록한 대로 실패했다. 전체176개 중174개 통과이며 전체 통과로 표시하지 않는다.

관련 Chromium 화면 검사는 신규6개, 백만 개 준비 취소·1,000개 화면 성능2개, 기존 도감·작은 화면·핀·소리 준비/일시정지/캐시4개가 통과했다. 일시정지 검사는 카메라 탐색을 허용한 요구사항에 맞춰 Canvas 전체 픽셀 고정 대신 구슬 물리 좌표와 경기 통계가 고정되는지 확인한다.

lint·Svelte 정적 검사·정적 build·공개 페이지 검증·REQ/화면 연결 검사·`git diff --check`를 모두 통과했다. 실제 청음과 실제 브라우저에서180경기 전체 시간을 재는 검증은 미확인이다. 계산상 재생 시간 결과와 구분한다.
