## 결정

`/aram-mayhem/augments/증강id` 증강 공략 페이지를 정적 HTML로 만든다. 처음에는 장갑 충격(`armored-impact`)과 벌이다!!!(`bees`) 2개다. 목록은 `src/lib/aram-mayhem/seo.js`의 `AUGMENT_PAGE_IDS`다. 결과 파일은 `build/aram-mayhem/augments/증강id.html`이다.

`장충 챔피언`·`벌이다 증강`처럼 증강 이름으로 찾는 사람에게는 챔피언 페이지보다 증강을 중심으로 모은 페이지가 맞다. 챔피언 페이지의 검색 설명에는 첫 증강 빌드만 들어가서, 트런들의 장갑 충격이나 바루스의 벌이다!!!처럼 다른 조합은 검색 문구에 드러나지 않는다.

증강 페이지는 가이드 데이터에서 그 증강을 쓰는 조합이 있는 챔피언을 모은다. 제목은 챔피언 페이지처럼 `증바람 장갑 충격(장충) 공략`으로 짧게 두고, 효과·어울리는 챔피언·템트리·패치는 검색 설명에 넣는다. 모든 챔피언이 같은 템트리를 쓰면(장갑 충격 고정 빌드) 템트리를 위에 한 번만 보여 주고 검색 설명에도 넣는다.

증강 페이지의 챔피언 이름은 챔피언 공략 링크다. 챔피언 페이지에 다른 챔피언 링크를 두지 않는 규칙은 그대로다. 허브는 챔피언 타일 아래에 `증강별 공략` 링크를 둔다.

## 검토한 대안

- 기존 검색 설명만 보강: 작업이 작지만 증강 이름 검색을 받을 대표 페이지가 없다.
- 모든 증강마다 페이지: 페이지 수가 늘지만 조합이 1~2개뿐인 증강은 내용이 얇다. 검색어로 많이 찾는 증강만 골라 늘린다.
- 장갑 충격 챔피언 추가: 디시 칼바람 갤러리에서 후보 16명을 찾았지만 근거가 대부분 추천 0개인 일반 글이고 스킬 선마와 고정 빌드 후기가 없어 넣지 않았다.

## 영향과 검증

- sitemap·방문 통계 공개 경로에 증강 페이지를 넣는다. 없는 증강 주소는 404다.
- 단위 테스트가 증강 페이지 주소, 제목, 어울리는 챔피언, 공통 템트리를 확인한다.
- build 검증이 허브 링크, sitemap, 제목, canonical, 챔피언 링크, 챔피언 목록 구조화 데이터를 확인한다.
- 배포 workflow가 `/aram-mayhem/augments/armored-impact`의 200 응답을 확인한다.
