# 의사결정 기록 2026-09-10: 설계 자료는 최신본과 Git 이력으로 관리

상태: 결정
일자: 2026-09-10

## 결정

- `docs/design/`에는 현재 IA·화면 문서, 최신 handoff와 마지막 Claude Design 요청문만 둔다.
- 번호별 package, 설계 문서 사본과 manifest를 없앤다. 과거 자료는 Git의 이전 commit에서 확인한다.
- UI 요구사항의 `design_ref`는 `docs/design/` 기준 화면 경로 목록으로 관리한다. 화면의 `연결 REQ`와 양방향으로 일치시킨다.
- 설계 승인 사실은 관련 commit이나 PR 설명에 명시한다. commit 자체를 승인으로 간주하지 않는다.
- handoff는 마지막 전달 시안이다. 새 전달본을 받으면 전체를 교체하며 구현 수정마다 재생성하지 않는다.
- 마지막 요청문은 `claude-design-DSN.md` 1개로 관리한다. 원본 DSN 번호를 출처로 남기고 현재 설계와 구분한다. 다음 실제 요청 때 같은 파일을 갱신한다.
- 현재 설계는 IA와 화면 문서로 확인한다. 실제 동작은 코드와 브라우저로 확인한다.

## 근거

- 번호별 설계 문서와 handoff를 복사하면 같은 파일을 반복 보관하게 된다.
- 현재 화면 문서는 이후 변경을 반영하지만 과거 package의 승인 내용과 요구사항 참조는 서로 달라질 수 있다.
- 전환 전 validator는 DSN-010의 요구사항 참조 불일치 21건과 handoff 파일 확인값 불일치 1건으로 실패했다. 이를 과거 manifest 수정으로 숨기지 않고 현재 문서의 연결을 검사하도록 전환한다.
- Git이 변경 이력을 보관하므로 번호별 사본과 파일 확인값을 별도로 유지할 필요가 없다.

## 전환과 영향

- 현재 IA와 화면 문서를 보존하고 DSN-010의 handoff 전체를 이동한다. 요청문은 DSN-009 내용을 기준으로 경로와 관련 안내를 갱신한다.
- 삭제 대상 자료가 commit에 저장돼 있는지 확인한다. Git 이력은 재작성하지 않는다.
- 제품 요구사항 본문과 기존 승인·보류 상태는 바꾸지 않는다. 승인 상태가 유지된다는 사실을 새로운 승인으로 표현하지 않는다.
- 검사는 화면 파일, ID, 문서 연결과 상태를 확인한다. manifest, 승인 시각과 파일 확인값 검사는 제거한다.
- 2026-09-05 Claude Design ADR의 기존 DSN·handoff 보관과 manifest 검증 부분을 대체한다. 초기 시안에만 선택적으로 사용하고 구현을 역동기화하지 않는 결정은 유지한다.
- 개인·공용 skill과 제품 코드는 변경하지 않는다.

## 검토한 대안

- 최신 manifest 1개 유지: 문서 수정 때 관리대장과 파일 확인값도 갱신해야 하므로 선택하지 않았다.
- 번호별 archive 유지: 현재 파일 목록의 중복이 남으므로 선택하지 않았다.

## 되돌리기

전환 이전 commit에서 설계 자료, 요구사항 참조와 validator를 함께 복원해야 한다. 파일 구조만 복원하면 검증 방식과 맞지 않는다. 이번 결정은 현재 파일 목록을 줄이며 Git 전체 이력의 용량까지 줄이지는 않는다.
