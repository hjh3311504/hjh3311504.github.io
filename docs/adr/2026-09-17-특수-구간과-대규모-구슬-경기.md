# 특수 구간·결승 연출과 대규모 구슬 경기

- 날짜: 2026-09-17
- 상태: 사용자 계획 구현 승인, 후속 음원·물풍선 제거 선택 반영
- 연결: REQ-MARBLE-001~004, SCR-WEB-004

## 결정과 이유

사용자가 설정 저장, 참가자 곱하기,60개 제한 제거, 특수 구간, 회전 판 결승, 당첨 연출, 미니맵과 내 맵 제작을 요청했다. 기존 공개 route·설정 키·기본3개 맵·일반11종 음원을 보존한다. 이전 ADR은 수정하지 않는다.

일반4구역·960개 사이에960높이의 연결 구간3곳을 둔다. 후속 요청으로 물풍선 장치는 삭제했다. 첫 구간에는 둥근 유도벽만, 다음에는5회 접촉으로 납작해지는 버터, 마지막에는 저항으로 가라앉는 젤리 연못을 배치한다. 버터는 왁뿌볼 Crack-A, 연못은 기존 물풍선 음원을 재사용한다. 팡파레만 새로 승인받은 Pixabay Tada Fanfare A를 연결했다. 모든 배속은 같은 파일·속도·음정을 사용한다.

원통은 회전 직선 판1개로 교체했다. 판180×16은4.8초마다 같은 속도로 회전한다. 초기 깔때기의 하단에서 여러 구슬이 서로 기대어 버티는 현상이 나타났다. 아래100~125높이의 벽을3차 곡선으로 수직에 가깝게 연결하고 좌우 수렴 높이를400/425로 엇갈렸다. 출구 폭40과 모든 충돌은 유지했다. 순위별 힘·결승 정체 바람·순간이동은 없다.

물리는 Web Worker에서1/120초씩 계산한다. 구슬 준비를256개 단위로 나눠 취소할 수 있게 했으며 주변 격자로 구슬 쌍을 찾는다. 정렬된 고유 번호 순으로 충돌을 처리한다. 출발 공간은 인원에 따라 늘어난다. 화면 밖 물리 계산은 계속하고 그림·순위 목록만 필요한 부분을 표시한다. 입력은 합계만 미리 계산하며 고정 상한을 두지 않는다.

결승 후보를0.3초 확인한 뒤 따라가며0.5배속과 최대1.6배 확대를 적용한다. 당첨 수가 채워지면1배속으로 복귀한다. 미니맵·당첨 목록·내 맵 편집기·경기장 패널은 재사용 컴포넌트로 분리했다. 설정 잠금 이유와 종료 후 편집·준비 취소를 항상 보여준다. 공용 Button·Surface·Dialog·SiteShell을 사용한다.

## 물리 측정

환경은 Apple M5, macOS26.6.2, Node24.11.0이다. 기본3개 맵×2/30/60개×난수10개로90경기를 비교했다. [측정 데이터](../marble-race-measurements.json)에 각 경기 시간과 순위대별 표본을 기록했다. 계산 시간은 병행 검사 부하가 포함되며 실제 브라우저 경기 소요 시간과 다르다.

## 분포와 우승 편향

30/60개 경기의2,700구슬을 좌·중·우 진입 위치와 진입 순위3분위로 나누었다. 표는 순위대별 우승자 수/참가 구슬 수를 계산한 뒤 세 순위대를 동일 비중으로 합친 값이다.

| 첫 연결 구간 진입 위치 | 이전 우승 비율 | 현재 우승 비율 |
| ---------------------- | -------------: | -------------: |
| 왼쪽                   |          2.74% |          1.74% |
| 중앙                   |          2.21% |          2.73% |
| 오른쪽                 |          1.67% |          1.93% |

현재 첫 구간 출구 분포는21.7%/57.3%/21.1%다. 마지막 연못 출구는19.1%/65.6%/15.3%다. 왼쪽 이점은 줄었으나 중앙 집중이 남아 있다. 양쪽 사이드의 우승 확률이 모두 동일하게 개선됐다고 단정하지 않는다. 이전 첫 연결 구간은 재질2 뒤, 현재는 재질1 뒤이므로 비교 지점도 다르다. 추가 구간별 분모·승자 수는 측정 파일에 남겼다.

## 화면·음향 검증

Chromium151 headless,1440×1000에서1,000개 경기의5초 구간을 측정했다. 화면 갱신105.6fps, 일시정지 버튼5ms를 기록했다. 병행 검사 중의 초기 구간 측정이며 경기 전체의 최저 프레임이나 모든 기기 성능을 보장하지 않는다. 준비 중 백만 개 입력 취소,1,001개 입력과 겹침 없는 준비, 중복 재질 내 맵 저장·복원도 검사한다.

음향 검사는 첫 화면 내 충돌·재생 명령·실제 출력 파형을 연결한다. 기존 고정 RMS0.01 기준은 단일 도각의 예상 출력보다 높아 겹침이 적은 출발을 실패로 판정했다. 원음 첫80ms의 RMS와 실제 재생 gain·기본 볼륨·스테레오 합산값으로 단일 타격의 예상 출력을 구하도록 수정했다. 실제 출력은 예상값의25% 이상, 출력 peak0.001 초과를 요구하며 기존 충돌/출력 지연 기준은 유지한다. 음원을 키우거나 충돌 전 소리를 추가하지 않았다. 실제 청감 만족도는 자동 파형 검사로 확정하지 않는다.

단위 테스트·저장·복구·버터 접촉·연못 탈출·Worker 배속 동일성, Chromium/WebKit 첫 출력, 모바일·전체화면·4개 당첨 방식·설정 잠금 안내·준비 취소와 미니맵을 검사한다. 최종 실행 결과는 작업 보고와 테스트 출력에 기록한다.

전체 경기 시간이 실제로 얼마나 걸리는지는 브라우저 부하와0.5배속 연출 시간에 따라 달라진다. 물리 측정의 경기 시간과 CPU 계산 시간, 짧은 화면 성능 측정을 서로 바꾸어 해석하지 않는다.추가 브라우저 검사에서1,000개 전원이113경기초에 도착했다. 준비 완료부터 실제133.70초가 걸렸고0.5배속 연출이 포함됐다.1초 단위 최저 화면 갱신은92.2fps였다.1,000등까지 결과 복사와 경기 종료 뒤 설정을 바꿔도 확정 결과가 유지되는 것을 확인했다. 이는 키보드 맵·첫 번째 방식의1회 측정이며 모든 기기·난수의 성능을 보장하지 않는다.
