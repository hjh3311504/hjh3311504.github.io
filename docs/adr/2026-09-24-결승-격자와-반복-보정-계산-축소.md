# 결승 격자와 반복 보정 계산 축소

- 상태: 적용
- 날짜: 2026-09-24
- 연결 요구사항: REQ-MARBLE-002, REQ-MARBLE-004
- 연결 화면: [SCR-WEB-004](../design/screens/SCR-WEB-004.md)

## 문제와 측정

[결승 보정 조기 종료와 충돌 탐색 재사용](2026-09-24-결승-보정-조기종료와-충돌-탐색-재사용.md) 뒤에도1000개·2배속 경기의 결승 밀집에서 실제 속도가 부족했다. 기존 최종 build 측정은105경기초부터 실제10초 동안약1.41배속이었다. Canvas는약120회/초로 갱신됐으므로 화면 갱신과 실제 경기 진행을 구분해야 한다.

실제 경기의105경기초 저장 상태를 다시 측정했다. 일반 블록 제거와 구슬 강제 고정을 하지 않은 자료다. 변경 전 물리 단계는 평균5.13ms였고, 결승 접촉 보정은 평균약3.06ms였다. 보정은 한 단계에 평균58.45회, 이웃 목록 재구성은 평균2.83회 수행했다. 결승 안의 구슬뿐 아니라 연결된 위쪽 구슬까지 평균854개가 대상이었다.

## 결정

- 결승 접촉의 격자는 현재 구슬의 높이 범위에 맞춘 연속 정수 배열로 조회한다. 재탐색 때 범위와 시작 위치를 다시 계산하고 필요한 만큼 배열을 늘린다. 음수 높이·큰 위치 변경·도착에 따른 인원 감소도 반영한다.
- 한 물리 단계 안에서 이미 정렬한 구슬 순서를 재사용한 뒤 현재 위치로 다시 정렬한다. 높이 내림차순과 같은 높이의 번호 오름차순은 유지한다. 후보 쌍의 순서도 유지한다.
- 재탐색은 계산용 위치 배열을 직접 읽는다. 모든 구슬 객체에 위치를 복사하는 작업을 줄인다. 벽 보정과 최종 결과 반영 때는 필요한 값을 동기화한다.
- 전체 구슬로 이웃 연결을 확인한 뒤 결승과 연결된 구슬·쌍만 반복 보정한다. 벽 후보도 그 구슬에 대해서만 만든다. 결승 밖에 있더라도 연결된 구슬은 포함한다.
- 큰 경기의 기본 결승 충돌은 속도만 바꾸므로, 위치가 그대로인 접촉 뒤의 벽·격자 재확인을 생략한다. 위치가 바뀌는 다른 접촉은 기존 처리를 따른다.
- 물리 간격1/120경기초, 내부 이동 분할, 반발계수, 지형, 회전바, 스킬, 종료 오차0.5·0.15, 최대512회는 유지한다. Worker의 시간 예산·상태 전달·남은 시간·이벤트 처리도 유지한다.

보정 순서 교대, 보정량 변경, 작은 겹침 생략, 이전 보정량을 더하는 계산도 임시로 비교했다. 효과가 작거나 느려진 방식은 제외했다. 이전 보정량을 더하는 방식은 저장 상태의 계산이 빨라졌지만1000개 밀집의 벽 통과·겹침 검사에 실패해 제외했다.

## 검증

출발·중간 밀집·결승 밀집의1000개·6경기초 상태와 이벤트를 변경 전 기록과 비교한다. 결승 기준값은 이번 변경 직전 코드를 사용한다. 격자 범위 변경과 새 이웃 연결도 별도 검사한다.

실제·표시 겹침1 이하,1000개·회전각4가지·35경기초 벽 통과 방지, 중앙 통로 진입, 번개 구슬 밀림과 얼음 고정, 배속별 재현성, 정지·재개·초기화, 스킬·효과음 이벤트를 관련 검사로 확인한다. 최종 build는1회 만들고 접근성 snapshot 뒤1440px·390px 화면을 확인한다.

## 검증 결과

- 관련 단위 검사128개 중126개를 통과했다.1000개 출발·중간·결승의6경기초 상태·스킬·이벤트가 변경 전 기준값과 일치했다. 격자 높이 범위 변경·도착·배열 순서 변경·새 이웃 연결도 통과했다.
- 실패한2개는 `finale-rebound.test.js`의 과거 회전바 비교다. 변경 전 코드를 별도로 실행해 같은 실패와 수치를 확인했다. 과거180 회전바 대비320 회전바의 역전 수는10회에서8회였다.290 대비320 회전바의 평균 상승은99.35에서114.53으로약15.3%였으며 테스트의20% 기준에 미달했다. 현재440 회전바의 검사와 구분한다. 테스트 기준과 지형·회전바 규칙을 바꾸지 않았으며 전체 단위 검사를 통과했다고 보고하지 않는다.
- 1000개·스킬ON 밀집에서 최대 실제 겹침은약0.6455, 표시 겹침은약0.5000이었다.1000개·회전각4가지·35경기초의 벽 통과 검사와 중앙 통로 진입 검사를 통과했다.60개 밀집은48.775~55.375경기초에 모두 도착했다. 번개 구슬과 연결된 번개 구슬의 회전바 밀림, 얼음 고정, 도착 구슬 제외, 보간의 실제 상태 보존을 확인했다.
- 0.25·1·2배속의 같은 경기 시각 결과가 일치했다. Worker의 남은 시간·상태 묶음·이벤트 보존, 정지·재개·초기화·늦은 응답 무시, 스킬과 효과음의 중복·누락 방지 검사도 통과했다.
- 최종 build의 Playwright11개를 통과했다.1440px·390px에서 화면10fps로 제한해도2배속 계산과 상태 전달이 이어졌고 정지·재개·초기화를 확인했다. 번개·바람 실제 발동, 번개 구슬의 회전바 밀림, 축하 효과 정리도 포함했다.
- 정적 검사 오류·경고0개, 변경 JavaScript의 lint·포맷, 정적 build 결과 검증을 통과했다. 최종 화면 검증용 build는1회 수행했다. 전체 lint와 다른 도구의 전체 테스트는 실행하지 않았다. 요구사항과 화면 문서의 연결은 이번에 변경하지 않았다.

## 성능 측정

다른 경기·테스트를 실행하지 않은 상태에서 변경 전후를 번갈아3차례씩 측정했다. 각 회차는 같은 실제105경기초 저장 상태에서5경기초·600단계를 계산했다. 단계마다 위치·속도·고정 기록·도착 여부·시각·이벤트를 해시로 비교했고6회 모두 같았다.110경기초의 도착 구슬도107개로 같았다.

| 지표                             | 변경 전  | 변경 후 |
| -------------------------------- | -------- | ------- |
| 물리 단계 평균의3회 평균         | 5.523ms  | 4.806ms |
| 느린 쪽5% 경계의3회 평균         | 10.071ms | 8.550ms |
| 600단계 순수 계산 시간의3회 평균 | 3.314초  | 2.883초 |

평균 계산 비용은약13.0% 줄었다. 파일 읽기·해시 계산은 단계 시간에서 제외했다. 브라우저의 실제 진행 속도와 동일한 지표는 아니다.

최종 build의1440×1000 브라우저에서 도각도각 키보드·1000개·난수47·마지막 방식·스킬/소리ON·2배속으로 측정했다. 출발0.158~20.092경기초의 실제10.001초는약1.993배속, 상태 수신52.2회/초, Canvas 그리기120.0회/초였다.

결승105.042~122.292경기초의 실제10.001초 측정은약1.725배속이었다. 시작 때 결승에361개, 종료 때350개가 있었다. 상태 수신은38.9회/초, Canvas 그리기는120.0회/초였다. 이전 기록의 같은 설정·105경기초 시작약1.412배속 대비약22% 개선됐다. 출발과 달리 **심한 밀집에서2배속 유지는 아직 달성하지 못했다.** 이 비교는 각10초 구간의 브라우저 측정이며 모든 밀집 상황이나 기기의 속도를 보장하지 않는다.

실제105경기초 저장 상태의 별도 안전 검사에서도5경기초 동안 실제 겹침 최대0.499996, 보간 겹침 최대0.499986이었다. 벽 반대편 이탈과 중앙 입구를 거치지 않은 골인은 없었고 표시 보정은 실제 상태를 바꾸지 않았다. 스킬 이벤트16개를 포함한 이벤트가 계속 발생했다.

접근성 snapshot을 먼저 확인한 뒤1440×1000과390×844 화면을 확인했다. 두 크기에서 가로 넘침이 없었고 모바일의 조작 버튼 줄바꿈과 정지 안내를 확인했다. 실제159.15경기초 장면은 결승349개·최대 겹침0.499970이었다. 정지 클릭부터 패널 확인까지59ms였다. 모바일은 데스크톱 브라우저의 화면 크기 검증이며 실제 휴대폰 성능 측정은 아니다.
