# 블록 재생과 받침판 출발·회전통 배출 수정

- 날짜: 2026-09-16
- 상태: 사용자 계획 구현 요청에 따라 적용
- 관련 요구사항: REQ-MARBLE-002, REQ-MARBLE-003, REQ-MARBLE-004

## 문제

원형 출발 통은 개방 전에 구슬을 아래로 모았다. 선두가 연 통로가 계속 비어 있어 후발 주자가 빠르게 따라붙었다. 반발계수 차이가 커 일부 재질은 반동이 거의 보이지 않았다. 마지막 통은 오래 갇힌 구슬이 정체 바람으로 빠져나가는 경우가 있었다. 기존 전체 완주 검사는 구슬별 긴 체류 시간을 놓쳤다.

## 결정

구역당20열×12행으로 줄여 블록 자리1,440개를 배치한다. 일반14종의 반발계수는0.65~0.75로 맞추고 마찰과 충돌면 기준의 계산은 유지한다. 위로 향하는 최소 속도는 강제하지 않는다.

파괴된 블록은 경기 시간2초 후 같은 자리에 반복 복구한다. 구슬이 겹치면 기다리며 복구 예정0.2초 전부터 윤곽을 표시한다. 복구는 무음이다. 블록 객체와 공간 격자를 재사용하고 복구 예정 목록을 예정 시각·고정 블록 순서로 처리한다. 파괴 회차를 기록해 한 회차의 중복 효과를 막는다. 실제 시간의 예약 함수는 쓰지 않아 일시정지 시 복구도 멈춘다. 같은 블록을 반복 파괴하는 것은 정체 해제의 새 진전으로 세지 않는다.

출발은 받침판4단에 최대15개씩 분산 배치하고1초 뒤 동시에 연다. 참가자와 위치의 연결만 난수로 섞으며 별도의 발사 힘은 없다. 중간2곳은 빈 통로와 젤로 나눈다. 사용자가 빈 통로를 빠른 길로 선택했으므로 통과 시간 균형 목표를 제거한다. 두 번째 젤은 반대편에 둔다. 통로 통과와 젤 접촉을 따로 기록한다.

마지막 통은 날개 길이를150으로 줄이고 축을 중심보다30 위로 옮긴다. 입구 분산판을230 위에 두고 하단 개구부를 약160으로 넓힌다. 날개 아래에는 중력으로 빠져나오는 공간을 둔다. 좌우 유도벽의 수렴 높이를25만큼 엇갈리게 한다. 유도벽 중심선을 연결하면 두께14와20의 차이로 위를 향한 턱이 생긴다. 안쪽 면을 골인 통로의 안쪽 면에 맞춰 이 턱을 제거한다. 마지막 구간에서는 정체 바람을 사용하지 않는다. 중앙 내부 폭40과 실제 아래 방향 도착 판정은 유지한다.

## 검증과 호환성

180경기 전체150초 완주 외에 구슬별 회전통 체류15초 이내를 검사한다. 첫 블록층 진입 폭480 이상, 중앙 분포, 조건부 역전 비율30% 이상, 복구 전후 추격·겹침 대기·반복 파괴·정체 판단을 검사한다. 출발·복구·회전통 화면은 모바일과 전체화면에서도 확인한다.

공개 route, localStorage 저장 형식, Pixabay 음원46개와 도감23종은 유지한다. 기존 ADR은 당시 결정을 보존한다.

## 물리 계산 결과

난수5·47·999·1·2·3·17·29·81·2026에서 맵6개·인원2/30/60명의180경기가 모두51.68~78.00초에 완주했다. 구슬별 회전통 체류 시간은 최대9.61초였다. 모든 구슬이 중간 통로2곳을 통과했으며 젤 통로는 실제 접촉도 확인했다.

30·60명 경기의 다음 재질층 진입률은 좌33.4%·중40.9%·우25.7%였다. 첫 블록층 진입 폭은 모든30·60명 경기에서480 이상이었다. 추격자가1초 이내에 회전통에 들어온150경기 중88경기(58.7%)에서 진입 선두가 우승을 놓쳤다. 이는 지정한 표본의 관찰 결과다.

첫 검증에서 키보드 맵60명·난수81의 출구가 막혔다. 이 실패를 통과 기준에서 제외하지 않고 유도벽 안쪽 면을 맞춘 뒤180경기를 다시 검사했다. 회전통의 체류 시간과 이 시작 조건은 자동 회귀 검사에 포함한다.

단위 테스트101개와 전체 Playwright55개가 통과했다. 출발 분포를 보완한 뒤 구슬 레이스 단위41개와 Playwright7개를 다시 통과했다. lint·Svelte Check·build·정적 페이지·문서 연결 검증도 통과했다. 브라우저에서 받침판 동시 개방, 복구 윤곽, 전체화면의 두 통로와 모바일30명 경기의 실제 골인 화면을 확인했다.
