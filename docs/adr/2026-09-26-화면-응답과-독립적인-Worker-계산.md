# 화면 응답을 기다리지 않고 Worker가 계산을 이어간다

- 날짜:2026-09-26
- 상태: 채택
- 관련: REQ-MARBLE-002/004, [이동 분할 적용 뒤 검증 결과](2026-09-26-이동-분할-적용-후-검증-결과.md)
- 승인: 사용자가 Worker의 대기 구조 개선·일반 밀집 계측·같은 원격 장비 비교 계획에 “진행해”로 승인했다.

## 원인과 결정

이전에는 화면이 Worker의 계산 응답을 처리해야 다음 계산을 요청했다. 원격 모바일의 응답 전달 대기는 평균23~35ms였다. 물리 계산이 끝나도 이 대기 동안 다음 시간을 계산하지 못했다.

Worker가 내부 시계로 지난 시간을 누적한다. 한 작업은 기본12ms 또는8물리 단계로 나누고 다음 작업은 MessageChannel로 예약한다. 계산할 시간이 아직 없을 때만 타이머로 기다린다. 화면은 시작·배속·정지 명령을 보낸다. 정지 명령을 처리하면 잔여 시간을 보존한 채 멈추며, 재개할 때 정지한 시간은 추가하지 않는다. 배속 전환 전에 쌓인 시간은 당시 선택 배속으로 계산한다. 매 물리 단계에서 연출 상태를 확인하므로 필수0.25배속도 그대로 적용한다.

화면의 수신 확인은 계산 진행을 막지 않는다. 일반 상태를 최대1개만 전달 대기 상태로 두고, 이후 위치·블록 변경은 다음 전달 때 인코딩한다. 충돌·스킬 이벤트는 그동안 모았다가 한 번 전달한다. 당첨·강제 감속·연출 종료·경기 종료는 해당 단계에서 바로 보낸다. 상태 번호로 마지막 수신을 확인해 오래된 확인 응답이 최신 상태의 전달 제한을 풀지 못하게 한다.

정지는 요청 번호가 일치하는 최종 상태로 확인한다. 정지 응답 전에 들어온 일반 상태가 정지 요청을 완료하지 않는다. 빠르게 재개해도 정지 응답을 먼저 기다린다. 정지 직전의 이벤트·당첨은 마지막 위치 상태와 합쳐 보존한다. 초기화와 화면 종료는 Worker를 종료하고 이전 Worker의 응답을 무시한다.

기존 명시적 `advance` 경로는 단위 검사와 같은 build의 비교용으로 유지한다. 실제 화면의 경기 진행은 자율 계산 경로를 사용한다. 지형·반발계수·구슬 이동 분할·스킬 규칙은 이번 변경에서 바꾸지 않는다.

## 일반 밀집 계산 실험

현재1000개 출발10경기초의 CPU 표본에서는 물리 단계 본문·구슬 쌍 분리·블록 충돌 처리가 대부분이었다. 거리 계산식 변경은 약3%에 그쳤다. 통과 지점 기록의 조기 제외는 반복 표본에서 개선이 일정하지 않았다. 격자별 후보 공유는 문자열 조회 비용 때문에 느려졌으며 구슬별 조회 기억을 함께 사용해도 유의미한 개선이 없었다. 세 실험은 `.context/autonomous-worker/`의 별도 모듈로만 남겼고 제품에는 채택하지 않았다.

## 비교 방법

같은 원격 실행과 같은 build에서 먼저 이전 요청 방식을 검사 브라우저의 Worker 어댑터로 재현한다. 물리·그림·상태 전달 형식과 브라우저는 동일하다. 이전 commit 전체를 다시 build한 비교는 아니며 요청 스케줄링 방식만 비교한다. 이후 실제 자율 계산 방식으로 같은 성능 검사를 수행한다.

비교 기준 실행은 기존 문제를 재현하므로 그 실패만 현재 제품의 실패로 집계하지 않는다. 현재 제품의 성능 검사 기준1.9~2.1배속·30fps·버튼200ms는 유지한다. 기준 실행 보고서와 현재 실행 보고서를 따로 보존한다. 계측은 물리1단계·Worker 계산 묶음·인코딩·응답 전달·복원·보간·그리기를 나눈다. 자율 계산에는 요청 왕복 시간이 없으므로 이전 요청 시간과 같은 이름으로 보고하지 않는다.

## 검증 기록

- Worker·내부 시계·상태 전송·계측 단위 검사17개가 통과했다.500ms 동안 수신 확인을 보내지 않아도 계산이 계속됐고 큰 상태는 쌓이지 않았다. 정지 상태와 모든 이벤트가 직접 계산과 일치했다.
- 개발 브라우저에서10fps 화면·500ms 멈춤·정지·재개·초기화3개, 축하·스킬·효과음·모바일 화면14개, 요청 방식 대조1개가 통과했다.
- 정적 검사 오류·경고0개와 UI 규칙 검사를 확인했다. 최종 build는1회 만들었고 정적 결과 검증이 통과했다.
- 최종 build의 구슬 레이스 브라우저 검사84개가 모두 통과했다. 다른 도구의 전체 브라우저 검사는 로컬에서 반복하지 않았다. 접근성 snapshot 뒤 모바일·데스크톱의 순위와 결승 화면을 확인했다.
- 일반 출발·진행 표본에서 데스크톱2배속은2.003~~2.005배·약60fps, 모바일390px·CPU4배 감속은2.005~~2.014배·52.5~60.2fps였다. 로컬 Apple M5의 결과이며 원격 PR 통과로 해석하지 않는다.
- 변경 코드 lint·포맷·workflow 문법·UI 문서 연결·변경 요구사항002/004 검사가 통과했다. 요구사항 검사는 기존 긴 문장 경고2개를 냈다. 물리 규칙은 바꾸지 않아 이전 동일 물리 코드의 실제·보간 겹침0.5 미만,1000개·회전각4가지 벽 통과 방지, 배속 재현성 기록을 유지한다.
