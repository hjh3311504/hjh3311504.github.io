# 구슬 충돌 이웃 재사용과 결승 계산 비용 축소

- 날짜: 2026-09-25
- 상태: 적용
- 연결 요구사항: REQ-MARBLE-004

## 배경

사용자가1000개·2배속의 결승 지연을 다시 보고했다. 결승0.25배속 강제는 필수이며 성능 개선 대상으로 해제하지 않는다. 이번 작업 시작 코드와 기존 실제105경기초 저장 상태를 별도로 보관했다. 기존 미커밋 변경을 기준으로 비교하며 과거 지형으로 되돌리지 않는다.

## 분석과 변경

실제 저장 상태의 CPU 분석에서 기본 구슬 충돌 탐색과 결승의 접촉 목록 재구성이 큰 비용을 차지했다. 기본 구슬 격자는 내부 물리 단계마다 전체를 비우고 다시 채웠다. 같은 칸에 남은 구슬도 주변9칸을 다시 조회하고 번호순으로 정렬했다.

- 구슬 격자를 내부 단계 사이에도 유지한다. 칸 이동·도착 때 연결 목록을 갱신하고 주변9칸의 변경 번호를 올린다.
- 주변 칸의 구성이 같으면 정렬된 이웃 번호 목록을 재사용한다. 거리·충돌·속도 판정은 현재 위치로 계속 수행한다. 구슬 쌍의 번호순 처리도 유지한다.
- 높이 범위의 시작점·필요한 용량·구슬 구성·배열 순서가 바뀌면 격자를 다시 만든다. 보정 중 범위 밖으로 이동한 구슬도 임시 칸에 기록해 탐색한다.
- 블록 접촉이1개면 같은 위치의 접촉면을 두 번 계산하지 않는다. 여러 블록에 닿으면 기존 접촉 순서와 재판정을 유지한다.
- 결승 보정의 거의 정렬된 높이 목록은 작은 순서 변경만 반영한다. 변화가 크면 기본 정렬을 사용한다. 연결 묶음의 대표 번호는 한 번씩 구해 재사용한다. 멀리 떨어진 벽은 큰 사각형 범위로 먼저 제외한다.

기본1/120경기초, 내부 이동 분할, 겹침 종료 기준과 최대 반복, 회전바·경사·반발계수·스킬·소리는 바꾸지 않는다. Worker 요청 예산·상태 전달과 화면 주기·경기 시간 처리도 그대로다. 겹침·벽 통과 검사를 생략하거나 경기 시간을 버리는 처리는 추가하지 않는다.

## 측정 조건과 한계

최신 작업 시작 build의 데스크톱 Chrome1440×1000·키보드·1000개·난수47·마지막·스킬ON·2배속에서는 결승50~~130경기초와190~~310경기초가약1.996~2.002배속, Canvas약60fps였다. 이 측정은 시작 때 소리를 켰지만 이후 OFF로 바뀐 기록을 확인했다. 따라서 소리ON 조건의 성능 근거로 사용하지 않는다. 이 조건에서는 사용자가 보고한 지속적인 지연을 재현하지 못했다. 따라서 반복 계산 축소를 사용자가 겪은 렉의 유일한 원인 해결로 단정하지 않는다.

CPU4배 감속 실험은 별도 스트레스 조건이다. 실제 시간30초 동안약1.993~~2.011배속이었고 상태 수신은약40~~41회/초로 떨어졌다. 이 실험도 물리 계산만의 감속률을 보장하지 않으므로 일반 기기의 성능으로 환산하지 않는다.

## 계산 비용 비교

원본105경기초 저장 상태에서10경기초·1200단계를 계산했다. 변경 전후를 번갈아4회씩 실행했고, 측정 중 다른 경기·검사·build는 실행하지 않았다. 파일 읽기와 상태 해시 계산은 단계 시간에서 제외했다.

| 지표                         | 변경 전 | 변경 후 |
| ---------------------------- | ------: | ------: |
| 물리 한 단계 평균의4회 평균  | 2.136ms | 1.832ms |
| 느린 쪽5% 경계의4회 평균     | 3.167ms | 2.867ms |
| 1200단계 계산 시간의4회 평균 | 2.563초 | 2.199초 |

평균 물리 비용은약14.2%, 느린 쪽5% 경계는약9.4% 줄었다.8회 모두 최종 구슬 상태와 전체 충돌·스킬 이벤트의 해시가 같았다. 이 수치는 Node 계산 비용이며 브라우저 실제 진행 속도 개선율로 바꿔 말하지 않는다.

## 안전 검사

- 관련 단위 테스트188개 통과. 기본 맵90경기의 완주·분산 검사도 포함했다.
- 1000개 밀집12경기초·스킬ON·회전각2가지: 최대 실제 겹침0.570464 미만, 표시 겹침0.499946 미만. 표시 보정은 실제 상태를 바꾸지 않았다.
- 1000개·회전각4가지·35경기초: 벽 반대편 이탈 없음. 중앙 통로 진입과 골인 검사 통과.
- 60개 밀집·회전각4가지: 최대 겹침0.621536 미만,38.608~42.125경기초에 전원 도착.
- 원본105경기초 저장 상태의5경기초 검사: 실제 겹침0.499951 미만, 표시 겹침0.498429 미만. 벽 통과와 잘못된 골인 없음. 벽438개·고무547개·스킬16개·회전바32개의 이벤트를 확인했다.
- 번개 고정 구슬과 연결된 번개 구슬의 회전바 밀림, 얼음 고정,0.25·1·2배속의 동일 경기 시각 결과, 스킬·효과음·당첨 이벤트와 Worker 남은 시간 보존을 확인했다.
- 정적 검사 오류·경고0개, 변경 코드 lint·포맷, 문서 연결·정적 build 검증 통과. 최종 build는1회 수행했다.
- 전체 lint·다른 도구의 전체 테스트는 실행하지 않았다. 과거 회전바 비교의 기존 실패2개가 있는 `finale-rebound.test.js`도 이번에 다시 실행하지 않았으며 전체 경기 테스트 통과로 보고하지 않는다.

## 최종 브라우저 검사

관련 Playwright11개가 통과했다. 접근성 snapshot 뒤1440px·390px 화면을 검사했다. 화면10fps 제한 상태의 독립적인2배속 계산, 일시정지·재개·초기화, 종료 뒤 설정 변경 시 준비 화면 복귀, 번개·바람 발동, 필수0.25배속과 연출 뒤 배속 복귀를 확인했다.

초기 수동 측정에서 소리OFF 또는 음량0으로 바뀐 기록을 발견했다. 사용자가 직접 소리를 껐다고 확인했으므로 앱 문제로 취급하지 않았고 소리 코드는 수정하지 않았다. 해당 기록은 소리ON·음량45 성능 근거에서 제외했다. 최종 비교는 별도의 headless Chrome에서 게임 소리ON·음량45·스킬ON을 구간마다 확인했다. 브라우저 출력만 `--mute-audio`로 음소거했으며 게임의 음향 처리와 효과음 재생 진단은 실행했다.

변경 전 비교에는 보관한 Worker JavaScript를 임시 정적 주소에서 불러왔다. 화면은 같은 최종 build를 사용했다. 이 진단용 Worker는 묶지 않은 소스이므로 전체 변경 전 build와 완전히 같은 비교로 보지 않는다. 최종 구현은 실제 build의 Worker로 측정한다. 진단용 파일은 측정 후 build에서 제거한다.

### 소리ON·음량45 최종 결과

도각도각 키보드·1000개·난수47·마지막·스킬ON·2배속,1440×1000에서 측정했다. 실제 시간은 `performance.now()`, 경기 시간은 Worker 상태의 `time`, 화면은 Canvas 전체 배경 그리기 횟수로 구분했다. 다른 경기나 검사를 동시에 실행하지 않았다.

| 최종 build 경기 구간  | 실제 진행 속도 |    Canvas | 최대 결승 밀집 |
| --------------------- | -------------: | --------: | -------------: |
| 50.000~70.033경기초   |    2.00315배속 | 59.995fps |          313개 |
| 70.033~90.050경기초   |    2.00149배속 | 59.995fps |          315개 |
| 90.050~110.058경기초  |    2.00051배속 | 59.990fps |          313개 |
| 110.058~130.050경기초 |    1.99903배속 | 59.996fps |          309개 |

상태 수신은약51.8~52.4회/초였다. 미처리 시간은 최대12.467ms, 마지막 구간 끝은0.067ms 미만이었다. 요청 간격 최대18.8ms로 기존80ms 입력 상한에 닿지 않았다. 미처리 시간이 계속 쌓이거나 이후 구간에 몰아 따라잡는 현상은 없었다.

변경 전 Worker 비교의 같은 시각대도약1.99988~2.00071배속이었다. Worker 요청당 순수 처리 시간은 가중 평균1.827ms에서1.731ms로약5.2% 줄었다. 이 보조 비교는 묶지 않은 이전 Worker와 최종 build Worker의 비교이므로 Node의 동일 형식4회 비교와 구분한다. **이 환경에서의 실제 배속은 변경 전후 모두약2배속이며, 사용자 환경의 렉과 같은 지속적인 감속은 아직 재현하지 못했다.** 계산 부담은 줄였지만 보고한 렉의 완전한 해결로 단정하지 않는다.

최종 실행에서 팝잇392회·파동53회·번개98회·바람31회·동결7회의 실제 재생 진단을 확인했다. 소리ON과 음량45를 측정 구간마다 확인했다. 접근성 snapshot 뒤1440×1000과390×844의 결승 화면을 확인했으며 가로 넘침과 조작부 잘림은 없었다. 모바일은 같은 데스크톱 브라우저의 화면 크기 검증으로, 휴대폰 실기 성능 측정은 아니다.

기존 미커밋 변경을 보존했다. 이번 작업은 기존 제품 파일 중 `physics.js`·`finale-contacts.js`만 수정하고 `marble-grid.js`를 추가했다. commit·push·배포는 하지 않았다.
