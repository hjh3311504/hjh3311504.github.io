# 큰 경기의 그리기 Worker 분리

## 배경

`0ccc743`의 원격 실행36243797892에서 데스크톱2배속은 출발2.002배속·진행2.000배속을 유지했다. 모바일CPU4배 감속의2배속도 출발2.007~~2.026배속·진행1.999~~2.010배속이었다. 남은 실제 시간은 모든2배속 표본에서0.001초 미만이었다.

그러나 모바일 화면은 출발28.7~~29.6fps로30fps 기준에 미달했다. 모바일1배속의 출발도23.4~~24.1fps였다. 진행 구간은 각각39.0~~40.6fps와32.0~~33.3fps였다. build·전체 단위 검사는 성공했으나 PR 전체 성공은 아니었다.

직전 코드의 로컬 실제 결승 측정은105~~145경기초에 데스크톱2.002~~2.004배속·약60fps, 모바일CPU4는1.998~~2.003배속·56~~58fps였다. 물리 지연과 그리기 지연을 구분해야 한다.

## 결정

200개 이상 실제 경기의 Canvas 그리기를 별도 Worker로 옮긴다. 물리 Worker와는 별개다. 기존 `renderer.js`의 그림 순서·색·글자·효과를 재사용한다. 표시 위치의 보간과 결승 겹침 보정은 기존처럼 화면 쪽에서 수행하고, 그 결과를 그리기 Worker에 보낸다.

- 같은 경기의 이름·맵·고정 정보는 처음에만 보낸다. 기존 전송 인코더로 위치 배열과 바뀐 블록을 전달한다.
- 그림 요청은1개만 진행한다. 기다리는 동안 모인 효과 이벤트는 다음 요청에 모두 넣는다. 물리 계산과 효과음은 그림 응답을 기다리지 않는다.
- Worker는 로컬 SUIT 글꼴과 OffscreenCanvas로 그림을 완성한다. 화면은 전달된 ImageBitmap을 복사한 뒤 닫는다.
- 경기 번호와 크기를 확인해 초기화·크기 변경 전에 만든 그림이 새 화면을 덮지 않게 한다. 화면 종료와 새 경기에서 Worker를 종료한다.
- 새 경기의 캐시를 비운 뒤 첫 이벤트를 적용해 첫 그림 전 이벤트도 보존한다.
- 준비 화면·200개 미만·미지원 환경은 기존 Canvas 그리기를 사용한다. Worker 생성·글꼴·실행 오류도 기존 방식으로 복귀한다.
- 지형·회전바·반발·스킬 규칙·필수0.25배속·물리 간격은 변경하지 않는다. 경기 시간을 버리지 않는다.

## 비교

로컬에서 더 강한 CPU12배 감속을 적용한 임시 비교는 기존 약20~~24fps에서 그리기 Worker 약39~~42fps로 개선됐다. 실제 경기 진행은 약2.00배속이었다. 이 임시 출력의 CPU4 문구는 복사된 이름이며 실제 설정은12다. 원격 CPU4나 실제 휴대전화와 같은 장비로 보지 않는다.

최종 build의 로컬 모바일CPU4·2배속은 출발1.995배속·59.8fps, 진행2.001배속·60.0fps였다. 화면 fps는 Worker 응답 수가 아니라 실제 경기 Canvas에 완성된 그림을 복사한 횟수로 센다.

최종 build로 실제 경기를 출발시켜105~~145경기초를 측정했다. 10초씩2회 관찰했으며 결승에는263~~289개가 있었다.

| 환경                  | 실제 진행 배속  | 화면 그리기      | 상태 수신          |
| --------------------- | --------------- | ---------------- | ------------------ |
| 데스크톱1440×1000     | 2.0015 / 2.0024 | 60.00 / 60.00fps | 52.40 / 51.60회/초 |
| 모바일 화면·CPU4 감속 | 2.0008 / 2.0033 | 59.60 / 59.88fps | 52.10 / 51.88회/초 |

모바일 수치는 데스크톱 Chromium에서 모바일 화면과 CDP CPU 감속을 적용한 결과다. 실제 휴대전화는 측정하지 않았다. 페이지 대상의 CPU 감속이 모든 Worker에 같은 비율로 적용되는지도 이 검사로 보장하지 않는다. 따라서 실제 기기의 전체 CPU·발열·전력 조건에서 같은 속도를 보장하는 수치로 해석하지 않는다.

HTML Canvas와 OffscreenCanvas는 둥근 블록 가장자리의 색 처리에 작은 차이가 있다. 같은144×144 타일 원본을 각각 만들면 색 채널327개가 달랐다. 같은 OffscreenCanvas를 메인 스레드와 Worker에서 실행하면 차이가0이었다. 이를 위치·그림 전송 오류와 구분한다. 기존 미지원 경로의 HTML Canvas 동작 검사는 유지한다.
