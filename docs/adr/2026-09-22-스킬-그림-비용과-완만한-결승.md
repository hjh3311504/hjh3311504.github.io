# 스킬 그림 비용과 완만한 결승

- 상태: 결정
- 날짜: 2026-09-22
- 연결 요구사항: REQ-MARBLE-001, REQ-MARBLE-002, REQ-MARBLE-003, REQ-MARBLE-004
- 연결 화면: [SCR-WEB-004](../design/screens/SCR-WEB-004.md)

## 배경과 사용자 선택

사용자는 스킬 발동 때의 끊김 개선, 도착 순위6열 복원과 완만한 직선 결승 벽을 요청했다. 경사는 수평 기준20°로 선택했다. 기존 회전바를 그대로 둔60개 재현에서는120경기초까지33개만 도착했다. 사용자는20°를 유지하면서 회전바 위치를 조정하도록 승인했다.

이 결정은 이전 [파동·결승 접촉·전체 미리보기](2026-09-22-파동-결승접촉-전체미리보기.md)의 양쪽 원호와 순위1·2·3열을 대체한다. 파동180, 겹침 보정, 전체 준비 화면은 유지한다.

## 결정

- 양쪽 벽을 수평 기준20°의 대칭 직선으로 만든다. 통로 쪽 끝은 기존 결승 시작점+400이며 바깥 시작점은 `결승 시작점+400−328×tan(20°)`다. 두께12와 출구 폭40을 유지한다. 그림·미니맵·충돌은 같은 블록을 사용한다.
- 회전축을 `(450, 결승 시작점+520)`으로 옮긴다. 길이320·두께16, 회전 속도·방향·마찰·탄성·시작 각도 난수는 유지한다. 강제 이동이나 추진력을 추가하지 않는다.
- 순위는 너비에 따라2·4·6열로 표시한다.36px 번호 구슬 옆에는 등수를 표시하고 진행률은 바로 아래 오른쪽에 둔다. 이름은 그 아래 최대2줄이다. 카드128px·행 간격140px로 맞추고 전체 스크롤·검색·선택·복사를 유지한다.
- 전기 고리와 작은 전기선을 별도 그림으로 저장해 재사용한다. 크기·표시 배율·동작 줄이기 설정별로 구분한다. 고리와 전기선의 회전 속도는 그대로 유지한다. 화면이 사라지면 저장한 그림도 해제되며 컨텍스트마다 최대16개 설정만 보관한다.
- 토네이도는 변하지 않는 삼각함수 값을 재사용한다. 매 프레임 나선의 좌표를 한 번만 계산하고 앞뒤 그림에서 공유한다. 화면 밖 스킬은 세로와 가로 범위를 모두 확인한다.
- 스킬 확률·효과·경기 시간·물리 계산 간격·효과음 정책은 바꾸지 않는다.

## 확인 결과

60개 밀집을 회전 시작 각도0·π/2·π·3π/2에서 검사했다. 서로 다른 시작 가로 위치를 쓰는 두 회귀 배치 모두29경기초 안에 전원 도착했다. 겹침 검사 배치의 완주 시각은27.96·24.56·24.19·27.35경기초다. 최대 구슬 겹침은0.622이며 벽 관통은 없었다. 별도 배출 검사에서 최대 도착 간격은1.94경기초였다.

기본3개 맵×2·30·60개×난수10개의90경기는 모두120경기초 안에 완주했다. 최대 완주 시각은67.08경기초였다. 출구에 대기 구슬이 있는데8.8경기초 동안 도착이 없는 배출 정체는 없었다. 기존 결승 체류15초 목표는30경기가 초과했으며 최대27.27경기초였다.

현재 지형의 접전32조합은 모두4경기초 안에 완주했고2조합에서 역전했다. 과거 직선과 회전바 길이를 비교하는32조합은 당시 지형을 고정해서 검사한다. 현재 지형에서 과거와 같은 역전 빈도를 보장하지 않는다. 회전바를 아래로만 옮긴 후보는 통로에서 순서가 고정되어 제외했다.

스킬 그림은 Chromium의720×680 Canvas에서 단독 측정했다.20프레임 준비 후50프레임을 측정하고 읽기 작업으로 그리기 완료를 확인했다.100개 구슬의 흰 전기 효과는 평균6.09ms에서1.95ms로 줄었다.30개는5.31ms에서1.53ms였다. 토네이도1개는3.63ms에서2.52ms였다. 바꾸지 않은 번개 본체도1.36ms와2.40ms로 차이가 났으므로 실행 환경의 흔들림이 있다. 이 수치는 전체 경기fps나 실제 휴대폰 성능이 아니다.

1000개 밀집의 물리 계산, 많은 스킬음의 동시 재생 등 다른 비용까지 없어진 것은 아니다. 이번 변경으로 경기 전체의 끊김이 모두 사라졌다고 해석하지 않는다.

## 최종 build의 화면 응답

1000개 실제 경기에서 출발과 이어지는 진행 구간을 각각5초간 측정했다. 스킬은 ON, 소리는 OFF이며 브라우저의 동작 줄이기 설정을 사용했다. 화면에서 실제로 그린 횟수를 세었다.

이 조건에서는30fps·버튼200ms 기준을 통과했다. 모바일 행은 데스크톱 브라우저에서 화면 크기와 계산 속도를 바꾼 시험이며 실제 휴대폰 측정이 아니다. 짧은 출발 구간의 결과를 결승1000개 밀집이나 모든 스킬 동시 발동의 성능으로 일반화하지 않는다.
