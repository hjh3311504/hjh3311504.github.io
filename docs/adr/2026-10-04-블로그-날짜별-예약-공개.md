# 블로그 날짜별 예약 공개

- 상태: 결정
- 근거: 2026-10-04 사용자가 글을 승인하고 서로 다른 등록일과 예약 공개를 요청했다.
- 변경하는 결정: [Markdown 블로그와 정적 게시](2026-09-29-Markdown-블로그와-정적-게시.md)의 ‘예약 발행은 제공하지 않는다’ 항목. 과거 문서는 보존한다.

## 결정

기존 `published`와 `publishedAt`을 사용한다. `published: false`는 항상 초안이다. `published: true`이면서 한국 날짜보다 공개일이 늦으면 예약이며, 공개일이 되면 공개 대상으로 판정한다. 파일 읽기 시 서버가 판정한 `publicationStatus`를 모든 공개 경로에서 사용한다. 방문자 시각으로 판단하거나 본문을 브라우저에 전달한 뒤 감추지 않는다.

예약 글은 공개일 전의 HTML·JavaScript·클라이언트 데이터·홈·관련 글·RSS·sitemap에서 제외하고 직접 경로도 404로 응답한다. 로컬 개발 서버에서만 예약 표시와 함께 미리 본다. 기존 정적 route와 저장 형식은 유지한다. `static/` 예제 파일과 공개 저장소의 글 원문까지 비공개로 만드는 기능은 아니다.

GitHub Pages workflow에 매일 UTC 15:17(한국 시간 다음 날 00:17) 실행을 추가한다. 기존 main build·검증·업로드·배포 절차를 재사용한다. 기본 branch 반영 전에는 활성화되지 않는다. Actions 지연·실패 시 다음 성공한 배포에서 기한이 지난 글도 함께 공개한다. 초 단위 공개 시각을 보장하지 않으며 공개일을 실제 실행일로 덮어쓰지 않는다.

## 검증

한국 시간 자정 직전·직후, 기한이 지난 초안, 예약 취소, 여러 날짜의 예약을 검사한다. production 렌더러에서 예약 직접 접근404와 홈·목록·관련 글·데이터·RSS·sitemap 제외 및 공개일 도달 시 포함을 확인한다. SvelteKit 데이터 요청은 HTTP 200 안의 오류 노드에404를 전달하므로 오류 노드와 내용 누락을 함께 검사한다. 전체 build 산출물에 예약 글 내용이 유출되지 않는지도 검사한다. 화면의 날짜·예약 표시와 검색 차단 정보는 브라우저에서 확인한다.
