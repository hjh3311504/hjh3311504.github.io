# 화면 범위의 충돌음·안정된 카메라와 회전 원통

- 날짜: 2026-09-17
- 상태: 사용자 계획 구현 요청에 따라 적용
- 관련 요구사항: REQ-MARBLE-001, REQ-MARBLE-002, REQ-MARBLE-003, REQ-MARBLE-004

## 문제와 결정

첫 블록에 닿을 때 구슬 중심은 아직 출발 구역에 있어 충돌음이 걸러졌다. 마지막 구간 전환은 이전 구역의 소리를 끊었고 유도벽에는 효과음이 없었다. 소리 선택을 공통 카메라 범위와 실제 접촉 위치로 바꾼다. 화면 밖52까지는 음량을 줄인다. 구역 변경만으로 잔향을 중단하지 않는다. 깔때기·원통·출구에는 기존 고무 범퍼 녹음을 사용한다. 음소거·일시정지·초기화·종료의 정리는 유지한다.

camera.js는 자동 추적 위치와 확대 비율을 계산해 그리기와 소리에 전달한다. 자동 추적은 아래로만 움직인다. 구슬이 화면 높이65% 아래에 도달하면48% 지점을 목표로 이동한다. 확대 비율은 마지막 구간 전체가 보이는 크기로 고정한다. 마지막 구간을 한 번 선택하면 화면을 고정한다. 사용자가 구슬을 직접 선택할 때만 위쪽 이동을 허용한다. 보간은 경기 배속과 무관한 실제 시간을 사용하며 전체 맵의 소리는 일반 추적 범위를 유지한다.

사용자는 빈 원통의 구멍1개가 회전하며 위에서 구슬을 받고 아래로 내보내는 방식을 선택했다. 마지막 왕복 장애물을 위쪽 깔때기·회전 외벽·고정 케이스·중앙 폭40 통로로 교체한다. 내부 날개는 없다. 고정 케이스는 위아래 포트 외 우회를 막는다. 회전 외벽과 같은 경계면을 사용해 사이에 구슬이 들어갈 틈이 없다. 원통 내부 진입과 아래 방향 판정선 교차를 모두 확인한다. 순위별 힘·전원 집결 대기·정체 바람·순간이동은 없다.

## 원통 치수와 조정

반지름140, 외벽 두께12, 반발계수0.35와 마찰0.05를 사용한다. 마지막 구간 높이는600이며 원통 중심320, 중앙 통로 시작540, 판정선570을 같은 배치에서 계산한다.

초기 구멍폭120·입출구폭100·일정 회전 속도에서는60명 밀집 조건의 대기가 길었다. 계획의 통과 시간 목표에 맞춰 구멍폭220·입출구폭200으로 넓혔다. 한 바퀴2.4초는 유지하고 속도만 주기 안에서 조정한다. 초기 위상과 방향은 경기 난수로 정하며 모든 구슬에 같은 규칙으로 적용한다.

한 주기의0~~20%는 위쪽 구멍 중심 전후0.25라디안,20~~35%는 옆면,35~~85%는 아래쪽 구멍 중심 전후0.25라디안,85~~100%는 반대쪽 옆면을 지난다. 각 구간의 각도는 부드러운 삼차식으로 연결한다. 구간 경계의 각속도는0이며 별도 정지 대기는 없다. 같은 식을 미분한 각속도를 충돌과 그림에 적용한다. 이 조정은 아래에서 구슬을 배출할 시간을 확보한다.

## 좌우 반동과 호환성

사용자는 좌우 반동 강화를 우선하고 중앙 진입률23.6%를 허용했다. 일반 블록의 모서리 반지름은10, 좌우 공기 저항의 감쇠계수는1.5로 변경한다. 반발계수0.55~0.65와 기존 접촉 마찰, 엇갈린 줄 배치,2초 복구는 유지한다. 임의의 옆 방향 힘은 추가하지 않는다.

공개 route와 저장 형식,4구역·960개 블록, 단일 출발 바, 도감23종과 기존 Pixabay 음원은 유지한다. 이전 ADR은 당시 결정 기록으로 보존한다.

## 측정 결과

맵6개·인원2/30/60명·난수10개(5,47,999,1,2,3,17,29,81,2026)의180경기가 모두27.13~52.51초에 완주했다. 마지막 구간의 최대 통과 시간은14.63초였다. 모든 도착 구슬이 원통 내부를 거쳤으며 충돌·블록 복구·중앙 통로 판정을 유지했다.

30명·60명 경기5,400개 구슬 중4,293개(79.5%)가 가로102 이상 이동했다. 중간 통로 다음 재질층의 좌·중·우 최초 진입은39.8%·23.6%·36.5%였다. 두 번째 구슬이1초 안에 마지막 구간에 진입한156경기 중107경기(68.6%)에서 진입 선두가 우승을 놓쳤다. 이는 검사한 난수 집합의 관찰값이다.

브라우저 검사에서는 첫 소리가 경기 시각4초 이내에 시작했고 마지막 원통 구간에서도 새 소리가 재생됐다. 카메라의 자동 역방향 이동과 확대 비율 변경은 없었다. 전체 Playwright58개는 순차 실행에서 통과했다.

해당 페이지의 Web Audio 출력만 녹음해 파형을 검사했다.2배속 녹음14.04초에서 첫 유효 신호는 실제1.425초에 나타났다. 시작과 마지막 구간 모두 출력이 있었고 최대 진폭은0.278, 잘린 표본은0개였다. 현재 도구는 오디오 입력을 지원하지 않아 직접 청음에 따른 음색 평가는 수행하지 못했다. 확인용 녹음은 output/playwright/cylinder-audio.wav에 있다.

전체화면 수동 검사에서 ResizeObserver의 알림 배열이 그리기 함수의 시간 인자로 전달되는 문제를 발견했다. 크기 변경 콜백을 인자 없는 호출로 바꾸고 모바일 크기 변경·전체화면 전환 뒤에도 시계와 카메라가 정상 진행되는 브라우저 검사를 추가했다. 일시정지 중 직접 구슬을 선택하면 다음 물리 프레임을 기다리지 않고 해당 위치를 보여준다.

최종 수정 뒤 관련 Playwright11개가 모두 통과했다. 새 크기 변경 검사와 모든 구슬 레이스 검사는 페이지 실행 오류도 함께 확인한다. 단위 검사, lint, Svelte 정적 검사, build, 정적 페이지·sitemap 검증과 문서 연결 검증도 통과했다. 모바일·전체화면을 직접 확인했으며 크기 변경 뒤에도 경기와 카메라 계산이 정상적으로 이어졌다.
