# 대규모 경기 계산과 화면 주기 분리

- 상태: 적용
- 날짜: 2026-09-23

## 배경

1000개·2배속에서 실제20초 동안 약19.3경기초만 진행했다. 화면은 충분히 갱신됐지만 물리 계산이 밀렸다. Worker는 요청당6ms 또는4단계만 처리하며 다음 요청도 화면 프레임까지 기다렸다.

## 결정

- 구슬 충돌 격자와 후보 배열을 경기별로 재사용한다. 격자의 구슬은 번호로 연결하며 후보는 기존 번호 순서로 정렬한다.
- 블록 격자는 숫자 좌표로 조회한다. 중복 후보 표시 배열과 접촉 후보를 재사용한다. 반환 순서는 유지한다.
- 이전 구슬 위치를 재사용하고 구간 통과 기준은 구슬마다 새로 만들지 않는다.
- 화면 프레임과 물리 요청을 분리한다. Worker 응답 뒤 계산을 이어 요청하고, 시간이 충분히 모이지 않았을 때만 타이머로 기다린다.
- 기존6ms·4단계 제한, 잔여 시간 보존, 물리 간격과 세분 계산은 유지한다. 일시정지·초기화·종료 시 예약을 정리하고 늦은 응답에는 기존 작업 번호 검사를 적용한다.
- 구슬 반발계수0.8·결승 지형·회전바·스킬·음향 정책은 유지한다.

## 검증

최적화 직전 코드와60개·1000개의 출발·밀집·결승을6경기초씩 비교한다. 위치·속도·블록·도착 순서·스킬·매 단계 이벤트가 같아야 한다.1000개 상태의 검증값을 회귀 테스트에 남긴다.

화면 갱신을10fps로 제한한 브라우저에서도 물리는2배속을 유지해야 한다. 정지·재개·초기화와 모바일 크기도 검사한다. 성능 보고는 실제 시간 대비 경기 진행량을 포함한다. 제한된 기기에서2배속을 항상 보장하는 변경은 아니다.

최종 로컬 build의1000개·2배속·소리와 스킬 ON 측정에서 실제20초 동안 약40.0경기초가 진행했다. 수정 전 같은 조건은 약19.3경기초였다. 데스크톱 Chromium·1440×1000·난수47·마지막 방식의 시작 구간 측정이며 결승 슬로모션은 없었다. 관련 단위 검사72개와 브라우저 검사14개를 통과했다.
