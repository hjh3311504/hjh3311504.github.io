# 첫 낙하 충돌음과 ASMR 질감 보완

- 상태: 사용자 후속 수정 요청 반영
- 연결: REQ-MARBLE-003, SCR-WEB-004

## 확인한 문제

사용자는 비누를 제외한 교체 소리가 ASMR 취지와 다르며 귀에 또렷하게 들어오지 않는다고 지적했다. 무음은 출발 바가 열리고 첫 줄 블록에 구슬이 한꺼번에 부딪히는 순간이라고 구체화했다.

기존 검사는 작은 파형 하나만 있으면 출력 성공으로 판단했다. 이 검사는 들릴 만한 질감이나 초기 소리의 크기를 확인하지 못했다. 실제 Chrome에서도 첫 줄 파괴와 재생 명령은 경기 시간 약2.72초에 함께 기록됐다. 재생 명령이 빠지는 현상은 재현하지 못했으므로 사용자의 무음 원인을 확정하지 않는다.

v2 샌드 첫 파일은380ms 중10ms 구간 RMS가0.02를 넘는 부분이 약50ms였고, 슬라임은480ms 중 약30ms였다. 작은 스파이크 뒤 약한 꼬리가 남았고 그 꼬리도 재질 동시 재생1개를 차지했다. 전체 길이 대신 유효 구간만 맞춘 음량 계산도 이러한 차이를 가렸다. 또한 이전 재생 중인 소리 수의 제곱근으로 새 소리의 음량을 나눠, 첫 동시 충돌의 뒤쪽 타격이 계속 약해졌다.

## 변경

- 비누 v2와 도각·팝잇·장치 WAV8개는 그대로다. 해시를 비교했다.
- 슬라임은 floraphonic의 Pixabay Slime Squish 12로 교체했다. 다른4종도 기존 원음의 다른 구간을 편집했다. 소재의 동작이 이어지는 구간을 사용하고 뒤따르는 질감이 있는 파일을 선택했다. 교체5종은 v3 파일명이다.
  슬라임600ms·샌드420ms·왁뿌볼400ms는 길이 대부분에 질감이 이어지게 했다. 정확한 샌드·왁뿌볼 대신 쓴 유사 소재는 출처에 그대로 명시한다.
- 조용한 유지 원음만 재생 시 최대2배 보정한다. 비누와 v3 파일에는 적용되지 않는다. 새 타격에만 누적해서 적용하던 감쇠를 제거하고 전체 압축기로 겹침을 제어한다. 동시 재생·간격 제한, 소리의 음정은 유지한다.
- 첫 충돌을 늦게 재생하거나 출발 전에 임의 소리를 넣지 않는다. 물리 계산과 첫 줄의 실제 파괴 시점은 변경하지 않았다.
- 개발 서버의 `?audioDebug`는 경기 시간4초 이전의 충돌·선택·생략·재생을 콘솔에 기록한다. 참가자 이름이나 명단을 기록하지 않는다.

## 검증 기준과 한계

첫 줄 `layer-0-0-*`의 파괴가2.9초 전에 기록되고 같은 충돌 묶음에서 재생돼야 한다. 첫 출력 이후80ms의 평균 출력 크기도 검사한다. 이는 기기 밖 실제 소리나 사용자의 청감을 대신하지 않는다. 미세한 파형 하나만 존재하는 조건으로 통과시키지 않는다.

물리·맵·통로를 변경하지 않았다. 기존90경기 시간 목표 실패는 이전 ADR의 기록을 유지한다.

## 실행 결과

음향 단위 테스트17개, 관련 기존 Playwright4개, 정적 검사·lint·build·문서 연결 검사를 실행했다. Chromium·WebKit의 개발 서버·정적 미리보기12개 조합에서 총60개 시작·재개 조건을 확인했다. 그중 첫 출발36건은 첫 줄 충돌 후 초기80ms RMS가0.0101~0.0424 범위였다. 피크 하나만 보는 이전 검사에 출력 크기 검사를 추가했다.

전체 브라우저 실행은11개 통과·1개 시간 초과였다. 실패한 WebKit 개발 서버 검사는 자산 파일 정리와 겹쳤으며 화면이 출발 준비 상태로 돌아와 있었다. 개발 서버의 자동 갱신 영향으로 추정한다. 파일 변경을 멈춘 뒤 해당 조건을 재실행해 통과했다. 이 실패를 사용자 무음 증상 재현으로 분류하지 않는다.

단독 이전·수정 비교5종과 같은 난수30명 경기의1배속·2배속 첫18초 녹음을 제공한다. 비누·도각·팝잇·장치8개 WAV가 그대로인지 해시를 확인했다. 실제 청감과 사용자 환경의 첫 낙하 무음 해소는 아직 사용자 확인을 기다린다.
