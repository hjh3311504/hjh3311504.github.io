# 밀린 경기 시간 보존과 계산 묶음

- 날짜:2026-09-26
- 상태: 채택
- 관련: [모바일 출발 계산 상한](2026-09-26-모바일-출발-계산-요청-상한.md), PR #33

## 확인한 실패와 원인

GitHub Actions 실행36229636510에서 build와 단위 검사는 성공했다. 브라우저151개 중 성능 검사3개가 실패했다. 모바일은390×844·CPU4배 감속, 데스크톱은1440×1000이다. 모두1000개·난수47·첫 번째 당첨·스킬ON·소리OFF 조건이다.

- 모바일1배속: 실제0.689~~0.703배,16.65~~17.10fps.
- 데스크톱2배속: 실제1.40~~1.46배,51~~52fps.
- 모바일2배속: 실제0.622~~0.648배,16.48~~16.82fps.

이전8단계 상한은 메인 화면 처리가 늦으면 Worker가 다음 요청을 기다리는 시간을 충분히 보충하지 못했다. 로컬 CPU12배 감속 추적에서도 Worker 계산보다 다음 요청을 기다리는 시간이 길었다. 또한 화면에서 다음 요청까지의 실제 시간을80ms로 잘라 초과 시간을 버리는 코드가 남아 있었다. 화면이 오래 멈추면 계산 여유가 생겨도 해당 시간을 복구할 수 없었다.

기존 코드의 성능 검사4개는 로컬 Linux 컨테이너에서 모두 통과했다. 이 환경은 Apple Silicon의 ARM 가상 환경이며 GitHub x64 서버를 재현한 것은 아니다. 로컬 통과만으로 원격 실패가 해결됐다고 판단하지 않는다.

## 결정

- 새로 지난 실제 시간과 이전 요청의 남은 시간을 모두 보존한다. 숨김·정지·재개는 기존 수명 관리로 처리한다.
- 처리할 실제 시간이1/30초를 넘으면 요청당48ms 또는32물리 단계까지 계산한다. 평상시는12ms 또는8단계를 유지한다. 개별 물리 단계는 중단하지 않으므로 예산을 한 단계 비용만큼 넘을 수 있다.
- 매 물리 단계에서 필수0.25배속과 당첨을 판정한다. 감속 전환·당첨·연출 종료가 생기면 즉시 상태를 전달한다.
- 구슬 그림을1024×1024 Canvas에 여러 개 저장하고 각 영역을 잘라 그린다. 구슬마다 별도 Canvas를 사용하는 비용을 줄인다. 번호·색·크기·그리는 순서는 유지한다.
- 1/120경기초 간격, 지형·회전바·반발·스킬 규칙과60회/초 상태 전달 정책은 유지한다. 미래 시간을 미리 계산하지 않는다.
- 성능 검사의 실제 배속·fps·정지 응답 기준과 GitHub 실행 환경은 바꾸지 않는다.

## 실험

CPU12배 감속의 구슬 그리기 단독 비교는17.55ms에서14.69ms로 약16% 줄었다. 같은 입력 이미지 비교에서 색상 채널 차이는 최대2/255였다. 이 값은 전체 게임 성능이나 GitHub 개선 수치가 아니다.

임시 Worker 응답 가로채기로32단계·48ms를 시험했을 때 CPU12배 감속에서 출발1.805배, 이후1.987배를 기록했다. 당시80ms 시간 제한이 남아 있어 출발에 버려진 시간을 복구할 수 없었다. 최종 소스는 이 제한을 제거했다. 생성 파일이나 검사 결과 파일을 수정하지 않았다.

## 검증

- 최종 build의 관련 브라우저11개가 통과했다. 아래 값은 출발5초와 다음5초의 별도 표본이다. 실제 배속은 Worker 경기 시간 증가량을 실제 경과 시간으로 나눴다. fps는 Canvas 그리기 횟수다.

| 데스크톱1배속            | 1.002          | 60.15    | 1.001          | 59.94    |

- 관련 단위 검사8개 통과.0.25·1·2배속의 Worker 결과가 직접 계산과 같다.32단계씩 전달해도 상태와 이벤트가 보존된다. 필수 감속과 당첨은 해당 물리 단계에서 즉시 전달된다.
- 1000개 밀집·회전각2가지의 실제 겹침 최대0.499984 미만, 표시 겹침 최대0.499464 미만.4·8·32단계 수신 간격을 함께 검사했다. 이 검사는 일반 블록을 제외한 밀집 배치다.
- 첫 build의 관련 브라우저29개 통과. 모바일·데스크톱 화면, 번호 잘림, 반동·번개,0.25배속 표시, 정지·재개·초기화를 확인했다. 접근성 snapshot을 먼저 확인한 뒤390px·1440px 이미지를 확인했다.
- 실제 화면 작업이500ms 멈춰도 이후3초 표본에서1.9~2.1배로 따라잡는 회귀 검사를 추가했다.
- Svelte 정적 검사 오류·경고0개, 변경 코드 ESLint·Prettier·UI 검사 통과.
- 첫 build 뒤 필수 감속 전환을 즉시 전달하도록 보완했다. 변경된 Worker를 검증하기 위해 build를 한 번 더 만들었다. 전체 로컬 검사는 반복하지 않았다.

## 한계와 재현

로컬 성능과 GitHub 성능은 구분한다. 이번 수정만으로 모든 저성능 기기의 심한 결승 밀집에서2배속을 보장하지 않는다. 선택2배속과 필수 결승0.25배속도 구분한다.

최종 build의 추가 CPU8배 감속 진단에서는 출발2.247배·32.16fps, 이후2.005배·31.09fps였다. 출발 표본은 이전에 밀린 시간을 따라잡아2.1배 상한을 넘었다. 이 진단은 수치를 수집했으며 정규 성능 기준 통과로 집계하지 않는다. 기록은 `.context/ci-perf/stress.log`다.
