## 찾은 그림 비용

이전 그림 페이지 방식은 구슬 하나를 페이지에 추가하고 곧바로 화면에 복사했다. 다음 구슬을 추가하면 앞서 복사한 큰 페이지가 다시 수정된다. 브라우저는 같은 페이지를 반복해서 전송하거나 복사해야 한다. 새 구슬이 화면에 들어올 때도 이 과정이 반복된다.

현재 프레임에 필요한 구슬 그림을 먼저 모두 준비한다. 그다음 이름·구슬·효과를 기존 순서로 화면에 그린다. 그림 페이지를 읽기 시작한 뒤에는 해당 프레임이 끝날 때까지 수정하지 않는다. 위치·색·번호·그리는 순서와 물리 계산은 유지한다.

## 검증

- 한 프레임 안에서 이미 복사한 그림 페이지를 다시 수정하지 않는 회귀 검사를 추가했다. 수정 전 build에서883번을 검출해 실패하는 것을 확인했다.
- 제품 변경 뒤 최종 build를1회 만들었다. 관련 성능·시간 보존·번호·모바일·데스크톱 표시 검사26개가 통과했고, 새 회귀 검사에서 중간 수정은0번이었다. 전체 브라우저 목록은 우선7개와 나머지146개다.
- 최종 로컬 모바일·CPU4배 감속·2배속은 출발2.010배·52.28fps, 이후2.006배·59.98fps였다. 데스크톱은 출발2.004배·59.97fps, 이후2.005배·60.00fps였다. 출발5초와 다음5초의 별도 표본이며 첫 그림 준비 시간과 구분한다.
- CPU8배 감속의 추가 진단에서는 출발2.018배·27.06fps, 이후1.994배·33.37fps였다. 출발 화면은30fps에 못 미치므로 정규 성능 기준 통과로 집계하지 않는다. 실제 배속과 화면 fps를 따로 기록한다.
- 정적 검사 오류·경고0개, 정적 build 검증과 변경 코드 ESLint·Prettier를 확인했다. CSS·Svelte 변경은 없다. UI 전용 검사에 JavaScript 파일을 넘긴 시도는 지원하지 않는 파일 형식으로 종료됐으며 통과로 집계하지 않는다.
- 일반 보고서와 계측 보고서는 HTML 보고서 폴더만 보존한다. 보고서가 이미 포함하는 영상·trace를 결과 폴더와 중복 업로드하지 않는다.
- 원격 실행끼리 하드웨어 차이도 확인할 수 있도록 운영체제·CPU 모델·코어 수·메모리·브라우저 버전을 검사 로그에 남긴다.
