# 팀 대진표 페이지 추가

- 날짜: 2026-10-16
- 상태: 채택
- 근거: 새 페이지 후보 조사에서 팀 대진표가 1위로 추천됐고 사용자가 선택했다. 연결 방식과 주소는 사용자가 확정했고 화면 시안을 승인했다.

## 결정

공개 route에 `/bracket`을 추가한다. 마지막 슬래시 없이 `build/bracket.html`로 배포한다. 홈·공통 내비게이션·sitemap에 진입점을 추가한다.

첫 버전은 팀 2개부터 32개까지의 한 번 지면 탈락하는 토너먼트 1종만 제공한다. 처음에는 16팀까지로 정했지만 개인전·학교·사내 대회와 Team Maker의 최대 20팀 결과를 받기 위해 32팀으로 늘렸다. 넓은 화면과 인쇄는 한 방향과 좌우 대칭 배치 중 덜 줄여도 되는 배치를 골라 영역에 맞춰 줄인다. 처음에는 17팀부터 대칭으로 정했지만, 1920×1080 화면에서 대진표 섹션을 스크롤 없이 보이려면 9팀부터 16팀까지도 대칭이 더 크게 보여 배율로 고르게 바꿨다. 화면은 최소 50%까지만 줄이고 그보다 작아야 하면 대진표 영역 안에서 스크롤한다. 좁은 화면은 라운드 탭과 한 방향 배치를 유지한다. 풀리그·더블 엘리미네이션·점수 입력·코트 시간표·PNG 저장은 후속 범위다.

입력 순서가 시드다. 부전승은 남은 팀 수가 홀수인 라운드에서만 1팀이 받는다. 같은 팀은 두 라운드 연속 부전승을 받지 않고, 그 조건에서 가장 높은 시드가 받는다. 짝수 라운드는 높은 시드와 낮은 시드를 붙여 1번과 2번 시드가 결승에서 만난다. 첫 라운드에 부전승을 몰아 2의 거듭제곱 칸을 채우는 방식은 6팀에서 부전승이 2개 생기고 실제 경기가 적어 사용자가 어색하다고 평가해 바꿨다. 무작위 배치는 팀 순서를 섞은 뒤 같은 배치를 적용한다.

대진표 계산과 화면은 직접 구현한다. brackets-viewer.js·brackets-manager는 여러 대회 방식과 i18next를 함께 가져온다. 단일 토너먼트에는 범위가 넓고 사이트 디자인 토큰에 맞추기 어렵다. 데이터 구조와 알고리즘만 참고한다.

Team Maker 연결은 결과 화면의 `대진표 만들기` 버튼으로 한다. 현재 팀 결과는 메모리에만 있고 `team-maker:v1`에 저장되지 않는다. 그래서 버튼을 누를 때 팀 이름과 팀원을 별도 키 `lake.bracket.import.v1`에 넘긴다. 대진표는 `lake.bracket.v1`에 1개만 저장한다. Team Maker 저장 형식은 바꾸지 않는다.

## 검토한 대안

- 대진표 페이지에서 `team-maker:v1`을 직접 읽기: 승패를 기록한 팀만 가져올 수 있다. Team Maker 저장 구조에 대진표가 묶인다.
- 연결 없이 시작: 경쟁 서비스와 구별되는 점이 사라진다.

## 영향과 검증

REQ·IA·화면 문서·README·개인정보 안내·AGENTS.md·CLAUDE.md·build 검증에 새 route와 저장 키를 반영한다. Team Maker는 결과 버튼 1개만 추가하며 기존 DOM 선택자와 상태 객체는 유지한다. 대진표 계산 단위 테스트, 브라우저 동작, 320px·390px·1440px 배치, 인쇄 1장 출력과 화면·인쇄의 같은 모양을 확인한다.
