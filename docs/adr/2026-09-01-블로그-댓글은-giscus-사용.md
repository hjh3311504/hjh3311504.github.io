# 의사결정 기록 2026-09-01: 블로그 댓글은 giscus 사용

상태: 결정
일자: 2026-09-01

## 결정

- 블로그에 댓글 기능을 추가할 때 GitHub Discussions 기반의 giscus를 사용한다.
- 현재는 기술 선택만 확정하고, 저장소 설정과 코드 구현은 댓글 기능을 실제로 추가할 때 진행한다.
- 댓글은 별도 백엔드를 구축하지 않고 GitHub Discussions에 저장한다.

## 핵심 근거

- giscus는 브라우저에서 GitHub API를 통해 동작하므로 현재 `adapter-static` 배포 방식을 유지할 수 있다.
- 별도 데이터베이스나 댓글 서버를 운영할 필요가 없다.
- 댓글과 관리 이력이 GitHub Discussions에 남아 현재 저장소와 함께 관리할 수 있다.

## 검토한 대안

- utterances: 댓글이 GitHub Issues에 저장되어 개발 작업용 Issue와 섞이므로 기각한다.
- Disqus: 무료 요금제에 광고가 포함되고 댓글 데이터가 외부 서비스에 종속되어 기각한다.
- 직접 구현: 별도 API, 데이터베이스, 로그인과 스팸 관리가 필요해 현재 블로그 규모에 비해 복잡하므로 기각한다.

## 영향 REQ

현재 연결된 REQ 없음. 향후 댓글 기능 REQ를 추가할 때 이 ADR을 연결한다.

## 영향 모듈

`src/routes/(blog-article)/+layout.svelte`, GitHub 저장소의 Discussions 설정

## 되돌리기 비용

구현 전에는 다른 방식으로 바꾸기 쉽다. 댓글이 쌓인 뒤에는 기존 Discussion 데이터 이전과 페이지 연결 방식을 함께 바꾸어야 하므로 비용이 중간이다.
