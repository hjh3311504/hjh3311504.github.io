# Markdown 블로그와 정적 게시

- 상태: 결정
- 근거:2026-09-29 사용자가 검토·보완된 전체 블로그 프롬프트대로 구현을 요청했다. 화면 구성·글 관리·검증 범위를 함께 승인했다.

## 배경

프로그램 홍보·사용 안내·업데이트 기록을 공개한다. 기존 블로그 삭제 결정 중 블로그·RSS 미생성 조건은 이번 결정으로 대체한다. 과거 ADR과 당시 기록은 보존한다.

## 결정

- `/blog`, `/blog/<slug>`, `/rss.xml`을 추가한다. 마지막 슬래시 없이 `build/blog.html`, `build/blog/<slug>.html`, `build/rss.xml`로 출력한다. 기존 도구 HTML 출력은 유지한다. 페이지 이동용 `__data.json`은 도구·블로그 폴더에 생성한다.
- `content/blog/*.md`의 YAML 글 정보와 Markdown 본문을 한 기준으로 사용한다. 작성자는 기존 운영자 Lake다.
- `src/lib/server/blog.js`가 파일 읽기·검증·렌더링을 맡는다. markdown-it14와 yaml2는 개발 의존성으로만 추가한다. Markdown 파서를 직접 만들지 않으며 원시 HTML 실행을 허용하지 않는다.
- 공개 글 목록으로 동적 route의 entries를 생성한다. 기존 crawl:false 설정을 유지한다.
- 초안은 개발 서버에서만 반환한다. 글 원문을 클라이언트에서 import하지 않는다. 최종 HTML·JavaScript·데이터·RSS·sitemap의 초안 제외를 검사한다. 공개 저장소 원문은 비공개가 아님을 안내한다.
- 목록 필터는 공개 글에 실제로 있는 분류만 사용한다. JavaScript 없이 기본 목록·본문·링크를 읽을 수 있다.
- 날짜는 YYYY-MM-DD로 저장하고 한국 시간 자정을 기준으로 공개 여부를 검증한다. 예약 발행은 제공하지 않는다.
- 공통 내비게이션·레이아웃·카드·버튼·빈 상태·개인정보 모달을 재사용한다. 본문 문단·표·코드만 전용 CSS를 사용한다.
- 기존 통계 수집 범위와 동의는 유지한다. 블로그 추적·광고·로그인·댓글·관리자 화면은 추가하지 않는다.
- 검색·공유·구조화 데이터·sitemap·RSS는 같은 공개 글 정보를 사용한다. 검색 등록과 AI 추천은 보장하지 않는다.

## 검증과 운영

`npm run test:blog`는 글 정보 오류·날짜 경계·초안·주소 중복·Markdown·RSS를 검사한다. `npm run verify:blog`는 실제 build의 본문·대표 주소·구조화 데이터·sitemap·RSS·초안 제외를 확인한다. production 렌더러를 임시 글 폴더에서 실행해 공개 글·초안404·빈 목록도 검사하며 추가 build는 하지 않는다. 기존 `verify:team-maker`에 연결해 PR과 배포에서 함께 실행한다. 관련 UI·브라우저 검사는 프로젝트 규칙을 따른다.

글 작성과 배포 후 Search Console 확인 절차는 README의 블로그 운영을 따른다. 예시 소개 글은 초안으로 두며 실제 외부 게시·계정 설정은 구현 완료와 구분한다.

공개 글이0개이면 SvelteKit의 미생성 경로 검사에서 `/blog/[slug]`만 허용합니다. 공개 글이1개라도 있거나 다른 경로가 빠지면 build를 실패시킵니다. 이 처리는 `scripts/blog_prerender.js`에서 검사하며 adapter의 strict 설정은 유지합니다.
