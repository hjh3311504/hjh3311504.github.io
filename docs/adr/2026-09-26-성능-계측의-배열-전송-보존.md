# 성능 계측의 배열 전송 보존

## 배경

그리기 Worker를 도입한 `6cb15a4`의 원격 실행36245792495는 성능 단계를 통과했다. 다만 데스크톱2배속은 첫 시도에서 미처 계산하지 못한 시간이0.209초로0.1초 기준을 넘었고, 재시도에서0.044초로 통과했다. 재시도 통과를 안정적인 여유로 해석하지 않는다.

| 원격 환경              | 실제 배속: 출발 / 진행 | 화면 fps: 출발 / 진행 |
| ---------------------- | ---------------------- | --------------------- |
| 데스크톱2배속 첫 시도  | 1.983 / 1.936          | 37.2 / 49.7           |
| 데스크톱2배속 재시도   | 1.982 / 2.004          | 37.8 / 48.7           |
| 모바일 화면·CPU4·2배속 | 1.984 / 2.007          | 34.2 / 47.1           |
| 모바일 화면·CPU4·1배속 | 1.004 / 1.008          | 34.5 / 47.2           |

직전 `0ccc743` 실행의 모바일2배속 출발28.7~29.6fps보다 개선됐다. 서로 다른 원격 실행이므로 장비의 순간 부하가 같다고 보장하지 않는다.

세부 계측 코드를 확인하니 난수만 고정하려고 감싼 `Worker.postMessage`가 두 번째 인수를 버리고 있었다. 제품은 배열 버퍼의 소유권을 Worker에 넘기지만, 이 계측 아래에서는 복사하게 된다. 같은 문제가 있는 화면 검사 도우미도 확인했다. 이 누락이 첫 시도의 지연 전체를 설명하는지는 별도 측정 없이 단정하지 않는다.

## 결정

- 성능·화면 검사에서 `postMessage`의 나머지 인수를 그대로 전달한다. 난수 고정과 가상 경기 응답은 유지한다.
- 성능 검사에서 실제 그림 배열을 보낸 횟수를 센다. 전송 뒤 원래 버퍼의 길이가0인지 확인해 소유권 전송이 보존되는지 검사한다.
- 실제 배속1.9~2.1, 계산 잔여 시간0.1초 이하, 그리기30fps 이상 기준은 변경하지 않는다.
- 제품 코드는 변경하지 않는다. 기존 최종 build로 관련 브라우저 검사만 다시 실행한다.

## 모바일 측정의 범위

Chromium의 [ThreadCPUThrottler 설명](https://chromium.googlesource.com/chromium/src/+/main/third_party/blink/renderer/platform/scheduler/public/thread_cpu_throttler.h)은 이 기능을 메인 스레드 감속으로 정의한다. [Emulation 구현](https://chromium.googlesource.com/chromium/src/+/main/third_party/blink/renderer/core/inspector/inspector_emulation_agent.cc)의 `setCPUThrottlingRate`도 페이지에서 이 함수를 호출한다.

따라서 모바일 화면·CPU4 결과는 화면 쪽 부하를 늘린 재현이다. 물리·그리기 Worker까지 실제 휴대전화와 같은 속도로 느려진 실험으로 보고하지 않는다. 실제 휴대전화의 CPU·발열·전력 조건은 미측정 상태다.

## 저장 상태 재측정

사용자가 제공한 `.context/slow-real-fixture.bin`의105경기초부터5경기초를 현재 제품 코드로 계산했다. 일반 블록 제거와 구슬 강제 고정을 하지 않았다. `node .context/slow-real-profile.mjs` 결과는1단계 평균2.069ms·95백분위3.703ms·전체1242ms였다. 기존 제공 기록의 평균5.45ms보다 약62% 작다. 이 계산 비용과 실제 브라우저의 경기 배속은 구분한다.

## 관련 검증

계측 수정 뒤 같은 build로 성능·포커스·결과 연출·결과 후 초기화10개, 진단용 모바일1배속1개, 화면 지연과 물리 일정4개가 재시도 없이 통과했다. 전송 후 남은 원본 버퍼는0개였다. 변경 검사 코드 lint·포맷과 `git diff --check`도 통과했다. 최신 원격 실행은 이 수정 commit으로 다시 확인한다.
