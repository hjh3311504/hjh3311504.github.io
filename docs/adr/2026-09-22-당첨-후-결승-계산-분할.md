# 당첨 후 결승 계산 분할

- 상태: 결정
- 날짜: 2026-09-22
- 연결 요구사항: REQ-MARBLE-004
- 연결 화면: [SCR-WEB-004](../design/screens/SCR-WEB-004.md)

## 배경

사용자는200개 경기에서 첫번째 당첨 이후 남은 구슬의 움직임이 끊기는 현상의 수정을 요청했다. 로컬 Chromium 계측에서는1배속의 위치 수신 간격이 최대96ms,2배속은267ms였다. 가장 긴 물리 계산의 약87~91%가 결승의 겹침 보정이었다. 화면 그리기는 계속됐지만 새 위치가 늦게 전달됐다.

## 결정

- 결승 겹침 보정의 최대32회·오차0.25와 구슬 처리 순서를 유지한다. 벽·회전바의 각도와 크기는 한 세분 계산 안에서 재사용한다. 닿을 수 없는 사각형은 거리 계산 전에 제외한다.
- 주변 구슬의 격자는 숫자 좌표로 조회하고 후보·정렬 배열을 재사용한다. 구슬 쌍의 중복 검사 표는2048개 이하에서만 사용하며, 큰 명단은 Set을 사용해 메모리가 인원수의 제곱으로 늘지 않게 한다. 임시 데이터는 경기 객체와 함께 정리된다.
- Worker는 고정 간격의 물리 단계를 마칠 때마다 경과 시간을 확인한다. 한 요청에서6ms를 사용했거나4단계를 처리했으면 현재 위치를 전달한다. 하나의 물리 단계 자체가6ms보다 오래 걸릴 수 있으므로 엄격한 응답 시간 보장은 아니다.
- 남은 계산 시간은 다음 요청으로 넘긴다. 화면에서는 새로 지난 시간에만 기존80ms 제한을 적용하고, 이미 받은 잔여 시간은 자르지 않는다. 정지 시간은 누적하지 않고 새 경기에서는 잔여 시간을 초기화한다.
- 당첨 시0.25배속을 끝내고 선택 배속으로 돌아가는 규칙, 스킬 확률·음향·도착 판정은 유지한다. 위치를 예측하거나 충돌 횟수를 줄여 끊김을 숨기지 않는다.

## 검증

최적화 이전의60개·200개 밀집 경기를 단계마다 비교한다.200개의12경기초 상태를 회귀 기준으로 남긴다. 기존 결승 겹침·관통·되튕김과0.25·1·2배속 동일성 검사를 실행한다. Worker의 시간 제한과 단계 제한은 가짜 시계로 따로 검사하고, 잔여 시간까지 처리한 위치가 직접 계산과 같은지 확인한다.

성능은 같은 seed47·기본 키보드 맵·소리/스킬ON·200개로1·2배속을 비교한다. 출발 구간을 같은 물리 계산으로 빠르게 진행하고 결승 전후를 실제 시간으로 측정한다. 계측 비용이 포함된 로컬 개발 화면 결과이며 실제 휴대폰 성능을 의미하지 않는다.

## 측정 결과와 한계

같은 조건의 당첨 후6초 계측에서 위치 수신의 최대 간격은1배속96.2→35.0ms,2배속266.7→37.6ms로 줄었다. 같은 구간의 가장 긴 Worker 계산은1배속94.4→27.6ms,2배속261.6→26.6ms였다.60개·200개의12경기초 비교에서는 매 단계의 위치·속도·도착·스킬 상태가 이전 코드와 일치했다.200개 밀집 구간의 순수 물리 계산 시간은 해당 비교에서 약30% 줄었다.

2배속의 당첨 후3~6초 밀집 구간은 실제3초에 약2.81경기초를 진행했다. 위치 전달 간격은 짧아졌지만 모든 구간에서 선택한2배속을 달성한 것은 아니다. 한 번의 물리 단계가 오래 걸릴 수 있고, 남은 시간을 버리지 않으므로 낮은 성능의 기기에서는 표시와 실제 시간 사이의 지연이 쌓일 수 있다. 충돌 생략 없이 전체 계산 비용을 더 줄이는 작업은 별도 개선으로 남긴다.
