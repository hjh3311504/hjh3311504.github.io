# PR 검사와 결승 회귀 기준 정리

## 배경

사용자가 PR 검사 실패 수정을 요청했다. PR33의 실행36115836327은 구슬 레이스 단위249개 중3개에서 실패했다. lint·UI 규칙·정적 검사와 Team Maker·QR 단위 검사는 이미 통과했다. 단위 검사 실패로 build와 브라우저 검사는 시작하지 않았다.

- `finale-rebound.test.js`의2개는 현재 길이448 배치가 아닌 과거 직선 지형과180/290/320길이를 비교했다. 연결 접촉 보정이 바뀐 뒤 역전 횟수10→8, 평균 상승 높이99.35→114.53으로 실패했다. 앞선 ADR에 실패를 기록했지만 현재 필수 검사에 그대로 남겨 둔 것이 누락이었다.
- `physics-optimization.test.js`의 결승 해시는 ARM에서 통과하고 GitHub의 Linux x64에서 실패했다. 같은 Node24.21.0의 macOS x64에서도 GitHub와 동일한 해시 `648a4a69…`로 실패했다. ARM의 해시는 `5ecbb0b0…`였다. Node24.21.0 ARM은 기존 기준을 통과했다.
- 두 CPU의720단계 상태를 비교하면304번째 단계에서 속도에 약10⁻¹⁴의 차이가 처음 생긴다. 밀집 접촉의 반복 계산 뒤에는 궤적과 스킬 이벤트도 달라진다. 마지막 값의 소수점을 조금 반올림하는 방식으로 해결할 수 있는 차이가 아니다.

## 결정

제품의 물리 코드·지형·회전바·반발계수·스킬·필수0.25배속은 바꾸지 않는다.

과거 배치 사이의 반동20% 증가와 역전 횟수 비감소는 당시 설계 비교 기록으로 보존한다. 현재 필수 검사는 사용자 후속 요청으로 확정한448길이·x160/+480축·40°/30° 경사를 사용한다. REQ-MARBLE-004에 남아 있던 과거 비교 문구도 이 범위로 갱신한다. 과거 ADR 본문은 수정하지 않는다.

- 양쪽 진입·시작 각도16개씩32조합이20경기초 안에 중앙 통로로 골인해야 한다.
- 양쪽 진입 모두 구슬 지름2개 이상 반동과 실제 역전 사례가 있어야 한다.
- 같은 최신 지형과 고정 접전에서 바가 없으면 선두가 먼저 골인하고, 바가 있으면 선두의 반동 중 추격 구슬이 추월해 먼저 골인해야 한다. 바를 끄는 비교는 원인을 확인하는 단위 검사에만 사용한다.
- 마지막1개 골인·통로 밖으로 완전히 밀어내기·벽 통과·겹침 검사는 기존 기준 그대로 실행한다.

1000개 결승의 장시간 해시 비교는 같은 실행 환경의 계산 자료 재사용 검사로 바꾼다. 별도 경기2개를720단계 진행한다. 한 경기는 계산 자료를 유지하고, 다른 경기는 매 단계 `structuredClone`으로 전체 물리 상태·Map·Set·객체 간 참조를 보존한 새 객체를 만들고 공간 격자를 다시 만든다. 새 객체는 기존 WeakMap 계산 자료를 재사용하지 않는다. 매 단계 구슬·블록·스킬·이벤트·도착 순서·회전바 접촉 기록이 오차 허용 없이 같아야 한다.

이 검사는 계산 자료 재사용의 오류를 찾는다. 독립 물리 엔진과의 비교는 아니므로 물리 규칙 자체의 회귀는 배치·반동·겹침·벽·배속 등 동작 검사로 확인한다. 출발·일반 밀집의 기존 해시는 변경하지 않는다. x64용 해시를 추가해 실패를 허용하거나 검사 항목을 건너뛰지 않는다.
