# 결승 연결 접촉과 보간 겹침 해소

- 상태: 적용
- 날짜: 2026-09-23
- 연결 요구사항: REQ-MARBLE-002, REQ-MARBLE-004
- 연결 화면: [SCR-WEB-004](../design/screens/SCR-WEB-004.md)

## 문제

0.1경기초마다 한 번씩 보정하는 방식은 한 구슬을 분리한 뒤 이웃·벽이 다시 밀어 넣는 겹침을 해소하지 못했다. 회전바에 직접 닿지 않은 결승 구슬은 추가 보정에서 빠졌다. 실제 위치가 분리돼 있어도 두 상태의 직선 보간은 구슬과 회전바를 겹쳐 보이게 했다.

## 결정

- 기본 구슬·블록 충돌과 빠른 이동의 세분 계산은 유지한다. 각1/120초 물리 단계의 마지막에 결승의 연결된 접촉을 함께 푼다.0.1초 예약과 한 차례 순회 제한은 제거한다.
- 결승에 들어간 구슬을 시작점으로 가까운 이웃의 연결을 찾는다. 회전바에 직접 닿지 않은 무리와 위로 튕긴 구슬도 대상에 포함한다.
- 구슬 쌍과 벽·회전바의 위치 보정을 반복한다. 오차0.15 이하에서 조기 종료하고 최대512차례로 제한한다. 보정량 계수는 기존1.4를 유지한다. 서로 파고드는 상대 속도만 제거하며 반발계수0.8·충돌음·스킬을 중복 적용하지 않는다.
- 반복 계산은 구슬 객체 대신 재사용하는 위치·속도 숫자 배열에서 수행한다. 숫자 격자와 쌍 목록·연결 배열·가까운 벽 목록도 재사용한다. 반지름 합에6의 탐색 여유를 둔다. 누적 이동 거리가3을 넘으면 후보를 재구성한다. 벽의 회전 좌표에서 거리를 계산해 먼 벽을 후보에서 제외한다. 후보를 만든 뒤3보다 크게 이동하면 전체 벽을 다시 확인하고 이동 경로 검사를 적용한다.
- 최근 한 물리 단계 안에 회전바에 밀린 구슬의 압력을 같은 무리의 번개 구슬에 전달한다. 번개 정지 시간과 자체 속도0은 유지한다. 바의 압력이 없는 번개 고정, 얼음 고정, 도착 구슬은 보호한다.
- 물리 단계 시작 위치와 보정 후 위치로 중앙 통로 진입·위쪽 재이탈·결승 교차 시각을 판정한다. 벽을 가로지르는 보정은 기존 이동 경로 검사로 막는다.
- 화면 보간에서도 같은 접촉 처리를 사용한다. 표시 좌표와 고정 기록을 복사해 실제 상태를 변경하지 않는다. 회전바는 표시 시각의 각도로 검사한다. 정지·골인·새 경기의 보간 초기화는 유지한다.

## 검증 기준

구슬 간 겹침1 이하를 실제 위치와 보간 화면에서 각각 검사한다. 회전바와 벽, 번개 구슬의 밀림, 도착 구슬 제외, 추가 효과음 없음, 배속별 동일 결과를 함께 확인한다.60개 밀집·회전각4가지의 완주와1000개·스킬ON 밀집을 포함한다.

1000개를 결승 앞에 강제로 배치하는 시험은 진입 공간의 일반 블록을 제거한다. 그렇지 않으면 일부 구슬이 재질 블록 안에 생성돼 결승 접촉과 무관한 초기 관통이 섞인다. 결승의 실제 벽·회전바·통로는 그대로 두며, 이전 벽 관통의 큰 변위 재현은 별도 검사로 보존한다.

위아래2개 시험의 과거10초 완주 제한은 현재13.2초 회전 주기와 분리한다. 겹침1 이하·회전바 접촉·반동 기준은 유지하고 완주는2회전 안에 확인한다.60개 밀집의60초 제한은 유지한다. 검사 기준을 낮춰 겹침을 허용하지 않는다.

이 결정은 [결승 보정0.1초 간격](2026-09-23-결승-보정-0.1초-간격.md)의 실행 간격·범위·순회 횟수를 대체한다. 이전 성능 측정값을 현재 결승 보정의 성능으로 사용하지 않는다. 큰 밀집은 반복 계산 비용이 증가할 수 있으므로 화면 갱신 횟수와 실제 경기 진행 속도를 구분한다.

## 검증 결과

- 관련 단위 테스트90개와 Playwright9개를 통과했다. 정적 검사에서 오류·경고가 없었으며 변경 파일 lint·포맷·요구사항2개·화면 연결·Git 공백 검사도 통과했다. 전체 lint와 다른 도구의 전체 테스트는 실행하지 않았다.
- 60개 밀집·회전각4가지의 최대 겹침은약0.622이며 전원48.8~55.4경기초에 도착했다.32개 접전은16번 역전했고 최대12.475경기초에 완주했다.
- 1000개·스킬ON·회전각0과3π/2의12경기초 시험에서 실제 겹침은 최대약0.343, 보간 겹침은 최대약0.207이었다. 실제 위치·속도·고정 기록이 화면 보정으로 바뀌지 않는 것도 확인했다.1000개·회전각4가지의35경기초 벽 관통 검사도 통과했다.
- 처음 구현한 객체 기반 반복 계산은 실제1000개 경기의 결승 밀집에서 진행 속도가약0.43배속까지 떨어졌다. 이후 숫자 배열과 가까운 벽 목록을 재사용하도록 수정했다. 같은 저장 상태의1경기초 비교에서 평균 물리 단계 비용은약14.5ms에서약6.3ms로 감소했다. 이 비교용 상태는 결승 위 구슬을 일시 고정하고 일반 블록을 제거했으므로 실제 경기 속도와 구분한다.
- 최종 build의 실제 브라우저·1440×1000·1000개·난수47·마지막 방식·스킬/소리ON·2배속에서 출발10초의 실제 진행은약1.99배속이었다. 결승 진입105.0~111.6경기초의10초 측정은약0.66배속·상태 수신43.6회/초·Canvas 배경 그리기119.6회/초였다. 표시 갱신과 실제 진행 속도는 다르며, 밀집에서2배속을 유지한다는 기준은 충족하지 못했다.
- 별도 실제143.5경기초 장면은352개가 결승에 있었고 구슬 간 최대 겹침은약0.100이었다. Playwright의 일시정지 클릭부터 정지 패널 확인까지약33ms였다. 접근성 snapshot 뒤1440px·390px 화면을 확인했으며 가로 넘침이 없었다. 실제 휴대폰 성능 측정은 아니다.
