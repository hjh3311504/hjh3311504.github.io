# 상태 전달60회와 결승 벽 통과 방지

- 상태: 적용
- 날짜: 2026-09-23

## 문제

계산을 화면에서 분리한 뒤1000개·2배속에서 큰 상태를 초당172~201회 전달했다. 화면 처리에 필요한 빈도보다 높았다.

1000개 밀집·회전바 시작 각도3π/2에서 약27경기초에112번 구슬이 왼쪽 경사 반대편으로 빠졌다. 밀집 보정으로 한 번에 약35만큼 이동해 최종 위치의 겹침 검사만으로 벽을 막지 못했다. 실제 좌표가 올바르더라도 두 상태의 직선 보간은 둥근 통로 모서리를 가로지를 수 있었다.

## 결정

- Worker의6ms·4단계 계산 한도와 잔여 시간 보존은 유지한다. 큰 상태만 실제 시간 기준 최대60회/초로 묶고 사이에는 가벼운 계산 완료 응답을 보낸다.
- 충돌·스킬 이벤트는 순서대로 모아 한 번씩 전달한다. 당첨·종료·슬로모션 전환은 빈도 제한을 기다리지 않는다.
- 일시정지 때 아직 보내지 않은 상태는 별도 요청으로 가져온다. 이 요청은 물리 시간을 진행하지 않는다. 새 경기에서는 모인 이벤트와 전달 시각을 초기화한다.
- 결승 벽을 구슬 반지름만큼 넓혀 보정 이동선과 첫 접점을 검사한다. 통과하려는 이동·속도 성분만 제거하고 벽을 따라가는 성분은 유지한다. 반발력과 소리를 추가하지 않는다.
- 중앙 폭40 입구를 구슬 반지름까지 포함해 아래로 지난 기록이 있어야 골인을 인정한다. 위로 돌아오면 기록을 지운다. 경기 중 생기는 내부 기록이며 공개 저장 형식에는 추가하지 않는다.
- 보간 좌표가 둥근 모서리 안으로 들어가면 표시 좌표만 보정한다. 실제 위치·속도·순위·고정 기록은 바꾸지 않는다.

## 검증 범위

1000개 밀집·회전각4가지에서 벽 반대편으로 빠지는지 검사한다. 재현된 큰 변위, 양쪽 경사·수직 통로, 정상 진입·진입 없는 골인 거부·위쪽 반동, 둥근 모서리 보간을 따로 검사한다.

일반 구간의 최적화 전 상태는 유지한다. 결승의 관통 수정으로 발생하는 순위 변화는 허용하며 과거 결승 상태 검증값을 그대로 적용하지 않는다. 배속별 결과 일치와 기존 전체 맵 완주·접전 검사는 유지한다.

## 검증 결과

- 관련 단위 테스트76개와 브라우저 테스트14개를 통과했다. 정적 검사와 변경 파일 lint·UI·문서 연결 검사도 통과했다. build는1회 수행했다.
- 1000개 밀집·회전바 시작 각도4가지를 각각35경기초 검사했고 벽 반대편으로 빠진 구슬은 없었다. 골인한 구슬은 모두 중앙 통로 진입 기록이 있었다.
- 로컬 production build의 Chromium·1440×1000에서1000개·2배속·소리와 스킬ON으로20초 측정했다. 경기는40.06초 진행했고 전체 상태 전달은 초당50.6~~50.7회였다. 이전 측정의172~~201회보다 줄었다.
- 같은 측정에서 Canvas 그리기는 초당약144회였다. 이 값은 그리기 호출 횟수이며 모니터에 실제 표시된 프레임 수와 구분한다. 실제 휴대폰 성능이나 모든 결승 밀집 배치의 성능을 보장하는 측정은 아니다.
