# 여러명 당첨을 도착 순위 범위로 지정

- 상태: 사용자 요청에 따라 구현.
- 요청: 여러명 방식을4~6처럼 지정해4·5·6번째로 도착한3개 구슬을 당첨시키기.
- 연결: REQ-MARBLE-001·003, SCR-WEB-004.

## 결정

여러명의 내부 ID `multiple`은 유지하고 숫자 인원 입력을 시작~끝 텍스트 입력으로 바꾼다. 양 끝을 포함하며 공백은 허용한다. 시작과 끝은1부터 전체 구슬 수 사이의 안전한 정수다. 역순·잘못된 형식·범위 초과는 시작 전에 거부한다. 같은 순위 범위는 한 구슬을 선택한다.

실제 판정선 교차 순서를 기준으로 해당 구간만 선택한다. 구슬 번호·이름을 범위로 해석하지 않는다. 중복 이름도 고유 구슬로 당첨될 수 있다. Worker에는 시작 순위와 당첨 개수를 함께 전달한다. 기존 함수 호출의 시작 순위 기본값은1이어서 이전 인원 방식의 호출은 같은 결과를 유지한다.

범위 앞 순위는 당첨 목록·축하·팡파레에서 제외한다. 범위 시작 순위 후보부터 결승 연출을 적용하고 한 명씩 도착하면 다음 선택 순위 후보로 옮긴다. 마지막 선택 순위가 도착하면0.25배속을 해제한다. 한 계산에 여러 당첨이 생겨도 구슬마다 한 번만 발표한다.

기존 localStorage 키는 유지하고 `rangeText`를 추가한다. 이전 `count`만 있으면 `1~count`로 복구한다. 새 저장에도 당첨 개수 `count`를 함께 남긴다. 명단·맵·n번째·소리 설정을 변경하지 않는다. 경기 시작 후에는 선택 범위를 잠그고 결과 복사에 범위를 표시한다. 전체 순위 복사는 유지한다.

## 검증

범위 입력·경계값·이전 설정 복구·새 저장·동일 이름의 실제 도착 순서·범위 밖 당첨 제외·결승 후보 전환·슬로모션 해제·동시 도착의 중복 방지를 단위 검사한다. 실제 Worker를 직접 물리 계산과 비교해 같은 범위 당첨자와 후보가 전달되는지 확인한다.

브라우저에서는 입력 오류·저장과 새로고침·모바일 폭·경기 중 잠금·범위 앞 순위 제외·선택 당첨 목록·축하·배속 복귀·결과 복사·재시작을 확인한다. 화면 검사는 재현 가능한 도착 상태를 사용하며 실제 Worker의 범위 판정은 별도 단위 검사로 확인한다. 기존 물리의 결승 체류·밀집 완주 목표는 이번 당첨 조건 변경과 별개다.

검사 결과: 관련 단위20개와 Chromium 회귀12개, 기존 설정 복구 화면1개를 통과했다. lint·Svelte 정적 검사·build·공개 페이지 검증·REQ/화면 연결 검사·`git diff --check`도 통과했다. 물리 배치와 음원은 변경하지 않아 전체 경기 시간 검사는 다시 실행하지 않았다.
