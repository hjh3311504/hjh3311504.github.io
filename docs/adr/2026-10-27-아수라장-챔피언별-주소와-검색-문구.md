## 결정

`/aram-mayhem`은 챔피언 타일을 보여 주는 허브로 두고, 챔피언마다 `/aram-mayhem/챔피언id` 공략 페이지를 정적 HTML로 만든다. 마지막 슬래시는 쓰지 않는다. 결과 파일은 `build/aram-mayhem/챔피언id.html`이다. `/blog`와 `/blog/[slug]`처럼 같은 이름의 HTML 파일과 폴더가 함께 있는 구조다. 예전 공유 주소 `/aram-mayhem#챔피언id`는 브라우저에서 새 주소로 옮긴다.

`#` 뒤의 값은 검색엔진이 다른 페이지로 보지 않는다. 그래서 31명이 한 페이지로 취급됐고, 정적 HTML에는 첫 챔피언(가렌)만 들어 있었다. 챔피언 주소마다 제목·설명·본문이 달라야 챔피언별 검색어에 맞출 수 있다.

허브의 챔피언 타일은 링크로 둔다. 검색엔진은 이 링크와 sitemap으로 챔피언 페이지를 찾는다. 챔피언 페이지에는 다른 챔피언 링크 목록을 두지 않는다. 위쪽에는 검색창 1개만 두고 입력할 때만 자동완성 목록을 띄운다. 등록 챔피언이 리그 오브 레전드 전체(173명)로 늘어나면 목록을 펼쳐 두는 방식은 첫 화면을 모두 차지하기 때문이다.

검색 문구는 `src/lib/aram-mayhem/seo.js`가 데이터에서 만든다. "증바람"과 챔피언·증강·아이템 별명(예: 마이, 신주, 새벽검)을 페이지 제목과 검색 설명에 넣는다. 별명 원본은 `docs/research/aram-mayhem/aliases.json`이다. 챔피언은 가이드에 없는 챔피언까지 173명 모두 넣고, 생성 script가 Data Dragon 목록과 대조한다. 별명은 사용자가 실제 검색어로 승인한 것만 쓴다. 이름 앞부분만 자른 줄임말(야스·헤카 등)은 대부분 뺐다.

GEO는 AI 답변이 페이지 내용을 인용하게 만드는 작업이다. 처음에는 템트리 요약 문장과 공략 질문을 본문에 넣었다. 같은 날 사용자가 화면을 간단하게 하려고 챔피언 페이지에서 요약·공략 질문·사용 안내를 뺐다. 그래서 템트리 요약은 검색 설명에만 남기고, 본문은 아이템·증강 카드의 정적 HTML로 내용을 전달한다. 구조화 데이터는 WebSite·WebPage·BreadcrumbList와 허브의 ItemList를 쓴다. REQ-SEO-001에 따라 FAQPage는 쓰지 않는다.

추천 기준 안내에서 디시인사이드와 통계 근거 표현을 뺀다. 이 가이드는 승률 통계로 매긴 티어표가 아니라 재밌다고 알려진 도파민 빌드 모음이라고 밝힌다. `강력 추천`·`추천` 표시와 조합 카드의 디시·유튜브 출처 링크는 유지한다.

## 검토한 대안

- 한 페이지와 `#챔피언id` 유지: 관리할 페이지가 적지만 챔피언별 검색어에 맞출 수 없다.
- 챔피언 페이지 아래에 다른 챔피언 링크 목록: 내부 링크가 늘어 검색에 유리하지만 사용자가 원하지 않았다. 허브 타일과 sitemap으로 충분히 찾을 수 있다.
- 챔피언 바꾸기 바와 펼치는 목록 패널(A안), 바에 검색창과 전체 목록 버튼(B안): 둘러보기는 쉽지만 C안보다 공간을 더 쓴다.
- 질문과 답에 FAQPage 구조화 데이터: Google이 일반 사이트에 FAQ 결과를 거의 보여 주지 않고 기존 정책과 맞지 않는다.

## 영향과 검증
