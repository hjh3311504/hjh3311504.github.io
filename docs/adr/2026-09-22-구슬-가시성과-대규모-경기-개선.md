# 구슬 가시성과 대규모 경기 개선

## 결정

사용자가2026-09-22 구현 계획을 승인했다. 이름표 뒤에 구슬·번호·고정 효과·추적 표식을 그린다. 순위는 같은 너비에서2·4·6열로 늘리고 내부 스크롤을 유지한다. 준비 화면의60개 미리보기와 전체 명단을 분리해 모든 참가자를 조회한다. 큰 명단도 현재 카드에 필요한 이름만 만든다.

마지막 후보가 결승에 진입하면 카메라를 아래 화면에 고정하지 않고 기본 배율로 추적한다. 기존 위치에서 확대·0.25배속을 시작하고 당첨 뒤에도 남은 구슬을 기본 배율로 따라간다. 당첨 판정 시점은 바꾸지 않는다.

Worker의 고정 간격 계산과 화면 표시를 분리한다. 두 수신 위치 사이를 보간하고 구슬·카메라·회전바에 같은 표시 시각을 사용한다. 미래 위치를 추측하지 않고 정지·고정·해제·골인·초기화 시 이전 위치가 남지 않게 한다. 실제 물리·순위·당첨은 원래 상태로 계산한다.

구슬 숫자 상태는 Float64Array로 전달하고 이름·색상은 준비 때만 보낸다. 고정 효과와 이벤트는 별도로 전달한다. 블록은 변경 가능한 속성만 비교한다. 미니맵 구슬을 Canvas로 전환하고 구슬 그림·이름 폭·화면 크기를 재사용한다. 화면 밖 블록은 세로 구역으로 검색한다. 기존150ms 순위 갱신과 즉시 당첨 반영은 유지한다.

## 왼쪽 곡면

왼쪽 직선을 아래로 갈수록 가팔라지는 원호로 바꿔 구슬이 안쪽으로 떨어지게 한다. 통로 쪽 표면은(12, 결승 시작점)에서(340, 결승 시작점+400)까지 이어진다. 중심은 약(-67.9024, 결승 시작점+400), 표면 반지름은 약407.9024다. 두께12와 회전바·오른쪽 벽·폭40 출구는 유지한다. 강제 이동이나 추가 힘은 넣지 않는다.

과거 회전바 길이 비교 검사는 당시 직선 지형과 시작 위치를 고정한다. 새 곡면 안쪽에 놓이는 기존 시작 좌표를 재사용하면 벽 바깥으로 공을 생성하므로, 곡면 비교는 양쪽 모두 통로 안에 들어오는100만큼 높은 시작 위치를 사용한다.

이 유효 위치의32조합은 직선에서 역전10회·최대13.63경기초, 곡면에서 역전8회·최대11.60경기초로 전원 완주했다. 역전 기회가 남아 있지만 해당 표본의 횟수는 줄었다. 모든 경기에서 역전이 늘었다고 해석하지 않는다. 곡면에1열로 배치한12개 중9개는 입구 전에 벽에서 떨어졌고 전원 완주했다.60개 밀집은 시작 각도4가지에서 약29.5~33.0경기초에 완주했다.

## 검증 기준

같은 난수의 Worker·직접 계산과0.25·1·2배속 결과를 비교한다. 표시 보간이 물리 상태를 바꾸지 않는지 검사한다. 기본90경기·60개 밀집·1열 배치·32가지 접전과 기존 스킬·동결·결승 판정을 확인한다.

모바일·데스크톱에서 전체1000명 순위 조회, 긴 이름, 마지막 후보 추적, 슬로모션 보간, 이름표 순서를 검사한다.1000개 실제 경기의 그리기 횟수와 버튼 응답을 측정하고30fps·200ms 기준을 적용한다. 실제 경기 진행 시간도 함께 기록한다. 모바일 크기·CPU 감속은 실제 휴대폰 측정과 구분한다.1000개 장시간 전원 완주 검사는 추가하지 않는다.

## 측정 결과

2026-09-22 로컬 Chromium에서1000개·난수47·소리 꺼짐으로 실제 Worker 경기를 측정했다. 출발 이후5초씩2회 측정한 값이다. 개발 서버의 최종 코드이며 실제 휴대폰이나 전체 경기 시간의 보장은 아니다.

| 환경                     | 화면 갱신      | 일시정지 응답 | 실제5초 동안 진행한 경기 시간 |
| ------------------------ | -------------- | ------------- | ----------------------------- |
| 1440×1000, CPU 감속 없음 | 119.9~120.3fps | 3.5ms         | 4.99~5.01초                   |
| 390×844, CPU4배 감속     | 39.7~47.7fps   | 10.7ms        | 4.92~5.08초                   |

출발·밀집·결승은 동일한1000개 배치에서120회 물리 계산과 상태 전달을 따로 측정했다. 상태 전달에는 데이터 생성과 복사를 포함한다. 비교 순서와 캐시 준비 상태가 물리 시간에 영향을 줄 수 있으므로 물리 시간의 개선율은 주장하지 않는다.

| 장면 | 변경 후 물리 계산 합계 | 변경 전 상태 전달 합계 | 변경 후 상태 전달 합계 |
| ---- | ---------------------- | ---------------------- | ---------------------- |
| 출발 | 367ms                  | 374ms                  | 107ms                  |
| 밀집 | 563ms                  | 400ms                  | 108ms                  |
| 결승 | 647ms                  | 359ms                  | 109ms                  |

같은3장면의 계산 결과를 화면에 고정해 Canvas 그리기 명령의 평균 실행 시간을 분리했다. 모바일 크기·CPU4배 감속에서 경기 화면은 출발4.96ms·밀집4.38ms·결승2.19ms, 미니맵은0.89~0.94ms였다. 이 측정은 화면 대역을 사용했으므로 실제 경기 진행 속도는 위 Worker 경기 결과로 판단한다.
