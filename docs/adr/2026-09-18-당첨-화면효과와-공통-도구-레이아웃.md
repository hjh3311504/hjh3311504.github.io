# 당첨 화면 효과와 공통 도구 레이아웃

## 배경

사용자가 당첨 효과 추가와 구슬 레이스의 공통 레이아웃 적용을 요청했다. 기존 축하 입자는 경기장 좌표로 그려져 카메라와 경기 정지에 영향을 받았다. 제목에는 다른 페이지의 하단 간격이 없었고, 페이지 전용 CSS가 공용 카드와 파란 포커스를 덮어쓰고 있었다.

## 결정

- 공용 `ToolPageLayout`에 제목과 하단32px 간격, 데스크톱·모바일 페이지 여백을 모은다. 기본 폭과 여백은 QR 페이지를 기준으로 하고 구슬 레이스는 넓은 경기장을 위해 최대1550px를 사용한다.
- 설정 제목은 `SectionHeader`, 설정·도감은 `Surface`의 card, 준비 패널은 raised를 사용한다. 공용 `ui-field`로 입력창의 테마와 포커스를 관리한다. 구슬 레이스의 중복 테두리·배경·초록 포커스를 제거한다.
- `WinnerCelebration`을 경기 화면 위에 배치한다. 당첨 이벤트마다 이름과 색종이를 실제 시간2.2초 표시한다. 같은 프레임의 당첨은 묶고 연속 당첨은 이전 효과를 교체해 누적하지 않는다.
- 마지막 구슬이 도착해 물리 계산이 끝나도 효과는 재생된다. 전체화면에서도 표시하며 클릭을 가로채지 않는다. 일시정지·초기화·페이지 종료 시 정리한다.
- 동작 줄이기는 이름만 표시한다. 기존 팡파레·당첨 목록과 당첨 판정은 유지한다. 경기장 좌표의 중복 축하 입자는 제거한다.

## 검증

- 브라우저에서 QR 페이지와 카드 배경·테두리·모서리, 제목 간격32px, 파란 입력 포커스를 비교했다. 데스크톱1440px와 모바일390px에서 가로 넘침이 없다.
- Worker가 보낸 당첨 이벤트를 기준으로 전체화면·연속 당첨·동일 이벤트 중복 방지·일시정지·초기화·최종 도착·동작 줄이기를 검사한다. 화면 검사는 도착 상태를 재현해 실행하며 실제 추첨 계산 검증과 구분한다.
- 기존 저장 검사는200ms 저장 전 null을 허용하도록 대기 검사를 수정했다. 테스트 브라우저에서 오디오 준비 실패가 발생해 설정 잠금·화면 효과 검사는 소리를 끈 상태로 수행한다. 이번 변경은 음원이나 오디오 재생 코드를 수정하지 않는다.
