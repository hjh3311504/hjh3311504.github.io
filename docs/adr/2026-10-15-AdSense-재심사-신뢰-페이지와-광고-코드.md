# AdSense 재심사를 위해 소개·방침 페이지와 광고 코드를 추가한다

- 상태: 결정
- 근거: 2026-10-15 AdSense 3번째 거절(가치가 별로 없는 콘텐츠) 대응 계획 사용자 승인
- 관련 요구사항: `REQ-WEB-027`, `REQ-WEB-026`
- 관련 화면: `SCR-WEB-007`

## 배경

2026-10-15에 세 번째로 거절됐다. 사유는 ‘가치가 별로 없는 콘텐츠’이고 소유 확인은 ads.txt로 했다. 9월 19일에 홈과 도구 안내를 보강했지만 결과가 같았다([점검 기록](../adsense-content-review.md)).

조사에서 다음 약점을 확인했다.

- 사이트 설명이 “도구와 프로젝트 소개”라 포트폴리오처럼 보였다.
- 개인정보처리방침은 모달뿐이라 독립 주소가 없었다. 소개 페이지와 이메일 문의도 없었다.
- 방침에 “광고 코드를 실행하지 않는다”고 적혀 있었고 build 검사도 광고 코드를 막았다.
- 도구 안내가 REQ와 달리 모두 접혀 있었다.
- 프로그램 소개 글 3개가 약 1,100자로 짧았다.

## 결정

- `/about`과 `/privacy` route를 추가한다. 개인정보처리방침 모달은 제거하고 모든 공개 페이지 footer에서 두 페이지로 연결한다. 2026-09-11의 “모달로 제공하고 새 route를 만들지 않는다”는 결정을 대체한다.
- 문의 수단에 이메일을 추가한다. GitHub 제보 창구는 유지한다.
- AdSense 코드를 모든 공개 페이지의 `<head>`에 1회 넣는다. 대상은 방문 통계의 공개 경로 목록과 같다. `/privacy`, 404·오류 화면, 초안·예약 글과 개발 서버는 제외한다. `/privacy`는 Google CMP 동의 메시지에 연결하는 페이지이며, Google은 이 페이지에 광고 태그처럼 동의가 필요한 스크립트를 두지 말라고 안내한다. 승인 전에는 수동 광고 칸을 만들지 않는다.
- 방침에는 Google 필수 고지(제3자 광고 쿠키, 맞춤 광고 해제 방법)를 적는다. 유럽 등 동의가 필요한 지역의 동의 창은 AdSense 계정의 Google CMP로 제공한다.
- 사이트·블로그 설명을 “파일·이미지·데이터 문제를 실험해 정리한 가이드와 브라우저 도구”로 바꾼다.
- 도구 안내를 REQ대로 기본 펼침으로 되돌리고 소개 글 3개를 보강한다.

## 검증과 한계

build 검사는 공개 페이지마다 ads.txt와 같은 게시자 ID의 AdSense 코드가 1개 있는지, `/privacy`와 404에는 없는지 확인한다. 브라우저 검사는 AdSense 요청을 빈 응답으로 바꾸거나 차단해 외부 서버에 연결하지 않는다.

이 변경이 승인을 보장하지는 않는다. 새 글의 색인과 사이트 평가에는 시간이 걸린다. 재심사 요청 시점, AdSense 게시자 ID 일치, Google CMP 설정은 계정에서 따로 확인한다.
