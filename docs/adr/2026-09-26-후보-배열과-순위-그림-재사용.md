# 후보 배열과 순위 그림 재사용

## 배경

`d84d0db`의 원격 실행36242818377은 lint·UI 규칙·정적 검사·전체 단위 검사·build를 통과했다. 성능 기준은 통과하지 못했다. 후속 전체 브라우저 검사와 정적 결과 검사는 실행되지 않았다.

같은 코드의 로컬 통과를 원격 통과로 간주하지 않는다. 원격 모바일은390×844 화면과 CPU4배 감속을 사용한 Chromium이며 실제 휴대전화 측정이 아니다.

## 측정과 결정

실패한 모바일1배속의 Chrome 작업 기록을 수집했다. 순위 카드의 구슬 그림 생성 함수가 자기 실행 시간약358ms를 사용했다. 물리 Worker에서는 구슬 충돌 처리와 주변 후보 조회의 비용이 컸다. 이 수치는 중첩 작업이나 브라우저의 감속 시간을 모두 합친 비용이 아니다.

- 후보 목록 저장소를 정수 칸 번호로 접근하는 배열로 바꾼다. 후보 순서·수정 횟수·범위 밖 이동 처리는 유지한다. 경기 범위를 다시 잡을 때 음수 속성까지 없애도록 새 배열을 만든다.
- 순위 카드가 다시 만들어져도 번호·색·배율이 같은 구슬 그림을 재사용한다. 문서와 글꼴 로딩 상태를 구분한다. 최근256개까지만 보관한다.
- 화면 밖 순위 카드의 그림을 그리지 않는 기존 정책은 유지한다. 다시 보이면 현재 번호의 그림을 복사한다.
- 지형·회전바·반발·스킬·필수0.25배속은 변경하지 않는다.

동일 브라우저에서1000개·난수47·스킬ON의20경기초를 계산했다. 기존1933.8/1889.1ms에서 변경1812.7/1816.8ms로약4~6% 줄었다. 각 실행의 전체 최종 상태는 정확히 일치했다. 원시 기록은 `.context/collision-render/array-browser.log`다.

추가 로컬 CPU12배 감속 실험에서 순위 그림 재사용 후 출발20.2fps·진행23.5fps를 기록했다. 원격 CPU4배 측정과 직접 비교하지 않는다. 이 임시 실험의 출력에 있는 CPU4 표기는 복사된 문구이며 실제 설정은12다. 이 결과도30fps 달성으로 보고하지 않는다.

녹화·Playwright 추적을 끈 대조 실험은 출발17.0fps·진행23.1fps로 큰 개선이 없었다. 녹화가 주원인이라고 판단하지 않는다. CSS 격리·강제 합성층·블록 그림 해상도 변경도 뚜렷한 이득이 없어 제품에 적용하지 않았다.
