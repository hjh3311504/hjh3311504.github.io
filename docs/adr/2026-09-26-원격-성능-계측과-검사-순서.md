# 원격 성능 계측과 검사 순서

- 날짜:2026-09-26
- 상태: 채택
- 관련: [밀린 경기 시간 보존과 계산 묶음](2026-09-26-밀린-경기시간-보존과-계산-묶음.md), PR #33

## 배경

실행36232011254의 lint·UI 규칙·정적 검사·전체 단위 검사·build는 성공했지만 브라우저152개 중5개가 실패했다. 모바일2배속은 실제1.21~~1.22배·15~~17fps, 데스크톱2배속은 실제1.20~1.36배였다. 로컬 macOS와 Linux ARM 환경의 통과를 원격 환경의 통과로 판단하지 않는다.

실패5개 중 하나는 모든 환경에서 반드시 상태 생략 응답이 발생해야 한다는 검사 가정의 문제였다. 계산 요청마다16.7ms 이상 걸리면 모든 응답이 상태를 담아도60회/초 상한을 지킨다. 나머지 성능 실패는 해결되지 않은 상태다.

## 결정

1. 기존 build를 브라우저가 받는 시점에만 계측 코드를 삽입한다. 제품 소스나 생성 파일을 수정하지 않는다. `MARBLE_PROFILE=1`일 때만 활성화한다.
2. 물리1단계, 상태 묶기, 상태 풀기, 표시 좌표 보정, Canvas 그리기 함수의 실행 시간과 횟수를 기록한다. 압축 함수 이름 대신 유지되는 문자열·객체 속성을 찾는다. 다섯 지점을 모두 찾지 못하면 계측 검사를 실패시킨다.
3. Worker 요청은 입력 대기, Worker 전체 처리, 출력 대기, 다음 요청까지의 대기로 나눈다. Window·Worker의 `performance.timeOrigin + performance.now()`로 시각을 맞춘다. 입력·출력 대기에는 브라우저 메시지 전달 비용과 각 스레드의 실행 대기가 포함된다.
4. 화면 프레임 함수의 실행 시간도 기록한다. 이 값에는 Canvas 그리기와 표시 좌표 보정이 포함되므로 중복 합산하지 않는다. Worker 전체 처리에도 물리·상태 묶기 시간이 포함된다. 서로 다른 스레드의 시간도 단순 합산하지 않는다.
5. 계측 없는 성능 검사를 먼저 실행한다. 실패한 경우에만 계측 검사를 별도로 실행한다. 계측 결과를 일반 성능 표본으로 섞지 않는다. 기존30fps·실제1.9~2.1배·남은 시간0.1초·정지200ms 기준은 유지한다.
6. 성능 검사에서 첫 표본이 실패해도 두 번째 표본과 정지 응답을 기록한다. 조건 하나라도 실패하면 검사 전체는 실패한다.
7. PR은 성능·시간 보존7개를 먼저 실행한다. 성공하면 나머지145개를 실행한다. 같은 목록을 포함·제외 기준으로 사용해 중복과 누락을 막는다. 앞선 검사 실패로 나머지를 실행하지 않았다면 전체 검사 통과로 보고하지 않는다.
8. 일반 성능 보고서와 실패 시 계측 보고서를 각각 GitHub artifact에7일간 보존한다. PR 실패는 그대로 유지한다. main build·배포 경로는 바꾸지 않는다.

## 검사 가정 보완

화면10fps 검사에서는 실제2배속, 상태 수신 발생, 최대60회/초와 정지·재개·초기화를 확인한다. 상태 생략 응답의 필수 발생 조건은 제거한다. 생략 응답의 발생과 이벤트 보존은 `frame-batch.test.js`의 고정 시계 검사에서 직접 확인한다.

500ms 화면 멈춤 뒤 실제2배속으로 따라잡는 검사는 그대로 유지한다. 이 검사의 원격 실패는 아직 해결되지 않은 성능 문제로 취급한다.

## 로컬 검증과 한계

- 계측 코드의 반환값·예외 보존과 대상이 없는 코드의 원형 보존을 검사한다. 관련 단위4개 통과.
- 압축된 실제 build에서 계측 검사4개 통과. 모바일·CPU4배 감속·2배속 출발 표본에서 물리1단계 평균1.938ms, 상태 묶기0.299ms, 풀기0.053ms, Canvas 그리기2.603ms였다. Worker 요청 평균9.387ms, 출력 대기9.265ms였다. 이는 로컬 계측값이며 GitHub 병목의 근거로 대신하지 않는다.
- 제품 코드가 바뀌지 않았으므로 최신 build를 재사용한다. 일반 성능 검사와 계측 검사는 별도로 실행한다.
- 추가 계측은 실행 시간을 조금 늘릴 수 있다. 프로파일러가 있는 수치와 없는 수치를 구분한다. 이번 변경 자체는2배속 미달을 해결했다는 뜻이 아니다.

## 실행

```shell
npm run test:e2e:built -- --test-list tests/team-maker-e2e/marble-priority.txt
MARBLE_PROFILE=1 npm run test:e2e:built -- tests/team-maker-e2e/marble-performance.spec.js --retries=0
npm run test:e2e:built -- --test-list-invert tests/team-maker-e2e/marble-priority.txt
```

임시 로컬 원본은 `.context/remote-profile/`에 보관한다. 원격 표본은 각 실행의 `marble-performance`와 `marble-diagnostics` artifact에서 확인한다.
