# 구슬 레이스 비주얼·테마와 메뉴 스크롤 변경 리뷰

- 리뷰일: 2026-10-15
- 기준: `origin/main` (`5a7a14273995f2372dff082f820b795dcef4a507`)
- 범위: 수정 파일28개와 새 파일 `arena-theme.js`·캐주얼 비주얼 ADR을 확인했다. 기존 `output/` 생성물은 리뷰 대상에서 제외했다.
- 작업 방식: 소스·테스트·문서를 수정하지 않았다. 이 보고서만 작성했다.

높음 문제는 발견하지 않았다. 중간1건을 확인했고, 낮음1건은 iOS 실기기 확인이 필요한 추정이다. 테마별 이름표 캐시와 Worker 경로에서는 오류를 발견하지 않았다.

## 발견 사항

### 중간 — 밝은 테마의 주요 경기 그래픽이 대비3:1을 충족하지 못함

**위치:** `src/lib/marble-race/arena-theme.js:5`, `:8`, `:14`, `:16`, `:17`. 사용 위치는 `src/lib/marble-race/renderer.js:283`, `:617`과 `src/lib/marble-race/components/RaceMinimap.svelte:185`, `:197`이다.

**문제:** 결승 벽·회전판·도착선은 구슬이 어디에 부딪히고 어디를 통과해야 하는지 알려 주는 그래픽이다. 밝은 배경으로 바꾼 뒤 이 그래픽들의 대비가 요청한3:1보다 낮아졌다. 블록의 아래쪽 그림자도 나머지 경계의 낮은 대비를 보완하지 못한다.

**근거:** 코드의 불투명 색을 sRGB 상대 밝기 공식으로 계산했다. 밝은 경기장 배경은 `#f4f8fb`이다.

| 요소              | 색        | 배경과의 대비 |
| ----------------- | --------- | ------------- |
| 결승 벽           | `#cdd8de` | 1.36:1        |
| 결승 회전판       | `#ef8f82` | 2.20:1        |
| 도착선            | `#55bfa6` | 2.09:1        |
| 일반 벽·고정 원호 | `#c3d0da` | 1.47:1        |

`light` 또는 밝은 운영체제의 `auto`에서 항상 적용된다. 미니맵도 같은 결승 색을 밝은 배경에 사용한다. 구슬 수와 관계없이 직접 그리기·Worker 모두 같은 색을 출력하는 것을 확인했다.

관련 상태 표시도 함께 확인해야 한다. 동결된 구슬의 외곽선은 `src/lib/marble-race/renderer.js:760`에서 여전히 `#e4faff`를 사용한다. 새 밝은 배경과의 대비는1.01:1이다. 바깥으로 드러나는 얼음 표식이 배경에 묻힌다. 이 부분은 기존 어두운 배경용 색을 밝은 테마에서도 사용하면서 생긴 회귀다.

**수정 제안:** 종류별 블록 색과 선택한 시안은 유지하되, 필수 경계·도착선·동결 표식에 테마별로 대비3:1 이상인 선이나 보조 표시를 적용한다. 결승 전용 색은 같은 색 계열에서 밝기를 조정할 수 있다. 팔레트 검사에는 이름표 글자4.5:1과 필수 그래픽3:1을 함께 넣는다.

### 낮음 — 하단 바운스가 되돌아올 때 아래로 내린 메뉴가 다시 나타남 (추정)

**위치:** `src/lib/components/organisms/SiteShell.svelte:122`–`:129`.

**문제:** `handleScroll()`은 `window.scrollY`를 문서의 실제 스크롤 범위로 제한하지 않는다. 하단에서 범위를 넘었다가 되돌아오는 바운스도 사용자가 위로 스크롤한 것으로 처리한다. iOS에서 아래로 내리기를 끝냈을 때 메뉴가 다시 나타날 가능성이 있다.

**재현 근거:** Chromium에서 `scrollY` 읽기값과 `scroll` 이벤트만 주입해 하단 바운스 순서를 재현했다. 최대 스크롤 위치1229px에서 `1209 → 1259 → 1279 → 1229`를 전달했다. 마지막 이벤트에서 메뉴가 `top:-64px`에서 `top:8px`로 바뀌었다. 코드 분기는 재현했지만 iOS 실기기의 실제 바운스는 확인하지 않았다.

**수정 제안:** 현재 위치를 `0`부터 `scrollHeight - innerHeight` 사이로 제한한 뒤 방향을 비교한다. 이전 위치도 같은 기준으로 저장한다. 하단 바운스와 음수 위치의 상단 바운스를 회귀 검사에 넣는다.

## 정상 동작 확인

- **캐시 갱신:** `renderer.js:526`에서 테마 변경 시 `labelFrames`를 비운다. `textSprites`의 키에는 테마와 글자색이 들어간다. `labels`에는 글자 내용과 너비만 저장하므로 테마 변경 시 유지해도 문제없다.
- **실제 픽셀 비교:** 2개·199개·200개·1000개 경기에서 `light → dark → light → dark`를 적용했다. 기존 캐시를 사용한 그림과 새 렌더러의 그림 차이는16개 조합 모두0이었다. 표시 렌더러와 기준 렌더러의 차이도 모두0이었다. 200개 이상은 실제 그리기 Worker를 사용했다.
- **사이트 테마:** `light`·`dark`·`auto` 각각에서 운영체제의 밝음·어두움 설정을 바꿨다. Canvas 배경·미니맵·OverlayCard·경기장 카드가6개 조합 모두 일치했다. 명시한 테마는 운영체제 변경에도 유지됐다.
- **감시 해제:** `watchArenaTheme()`의 해제 함수 호출 뒤 테마 속성과 운영체제 설정을 바꿔도 추가 콜백은 없었다. 페이지 정리 함수의 `stopTheme()` 연결도 확인했다.
- **메뉴:** 64px 이하 표시, 8px를 넘는 누적 방향 변화, 숨겨진 버튼의 초점 표시, drawer 열림, Escape 종료 후 초점 복원을 확인했다. 동작 줄이기에서는 전환 시간이0초였다.
- **스크롤 복원:** 동작 줄이기에서는 drawer를 닫은 뒤600px 위치로 즉시 돌아왔다. 일반 동작에서는 기존 `html { scroll-behavior: smooth; }`에 따라1000px 위치로 부드럽게 복원됐고, 최종 위치와 초점이 유지됐다.
- **1200px 경계:** 1201px의 고정 사이드바와1200px의 떠 있는 메뉴 전환에서 body 잠금이 남지 않았다. 아래로 스크롤해 숨겨 둔 상태는 경계 전환 뒤에도 유지됐고 위로 스크롤하거나 초점을 주면 표시됐다.
- **이름표 대비:** 일반/추적 글자는 밝은 테마10.35:1/14.63:1, 어두운 테마11.27:1/15.16:1로4.5:1을 충족했다.
- **성능 구조:** 구슬은 기존 그림 캐시를 재사용한다. 새 광택·음영은 캐시 생성 때 그리며, 준비된 구슬의 프레임별 복사 횟수는 그대로다. `drawMarble()`에 `shadowBlur`는 없고 결승 회전판의 흐림 효과도 제거됐다. 기존 전기 효과의 캐시 생성용 흐림은 남아 있다.
- **스타일·문서:** 삭제한 CSS 선택자는 `src/`에서 더 이상 사용하지 않았다. CSS 색상 토큰 규칙과 요구사항·화면 연결 검사도 통과했다. 승인 상태는 유지됐다.

## 테스트와 문서의 남은 보완점

- 수정된 렌더링 e2e는 기존 배경·고리 색의 감지 조건을 새 팔레트로 바꾼다. 예를 들어 `tests/team-maker-e2e/marble-rendering.spec.js:8`, `:33`은 밝음·어두움 중 어느 배경도 허용한다. 현재 선택한 테마가 정확히 그려졌는지, 전환 뒤 이름표 캐시가 바뀌었는지는 검사하지 않는다. 위의 수동 브라우저 비교는 통과했지만 이 검증은 저장소 테스트에 아직 남아 있지 않다.
- 기존 `tests/team-maker-e2e/marble-render-worker.spec.js:61`의 옵션에는 테마가 없고 실행 중 테마 전환도 없다. 이 검사에 밝음↔어두움과 재전환을 넣으면 Worker·이름표 캐시 회귀를 함께 잡을 수 있다.
- `tests/team-maker-e2e/navigation.spec.js:51`의 새 검사는 실제 버튼 좌표를 확인하므로 숨김·재표시를 검증한다. 다만 초점은 `button.focus()`로 주고, drawer 종료 후 `scrollY`를 비교하지 않는다. 64px 경계·실제 Tab 이동·스크롤 복원·바운스·1200px 전환은 자동 검사 범위 밖이다.
- 밝은 당첨 별·테두리 `#c98a05`는 카드 `#fffdfc`와2.91:1이다. 요청한 그래픽 대비3:1에는 조금 못 미친다. 이름으로도 당첨을 알리고 별은 장식이라 별도 기능 결함으로 세지는 않았다. 색을 조금 더 진하게 하면 여유를 확보할 수 있다.
- 새 ADR의 `:26`에 있는 “그리기 횟수와 캐시 구조는 바꾸지 않는다”는 문구는 캐시가 준비된 프레임을 뜻하도록 좁히면 정확하다. `drawMarble()`의 최초 그림 생성은 `fill()`1회에서3회로 바뀌었다. “프레임별 구슬 복사 횟수와 캐시 구조를 유지한다”로 쓰면 구현과 맞는다. 전체 성능이 개선됐다는 수치는 이번 리뷰에서 측정하지 않았다.
