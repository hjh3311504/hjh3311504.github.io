## 코드가 숫자로 바뀌면 원래 값을 잃을 수 있습니다

우편번호, 상품 코드, 계정 번호처럼 계산하지 않는 값도 숫자만으로 이루어질 수 있습니다. CSV에 `00123`이라고 적혀 있어도 스프레드시트가 숫자 `123`으로 읽으면 앞의 0이 사라집니다. 15자리를 넘는 숫자(16자리 이상)는 Excel에서 정밀도가 줄어들 수 있습니다.

이런 값은 **숫자가 아니라 문자 그대로 보관해야 하는 코드**입니다. 이미 바뀐 셀의 표시 형식만 고쳐도 사라진 0이나 잘린 숫자가 되돌아오지 않습니다. 원본 CSV를 남겨 두고 다시 가져오세요.

## 같은 CSV를 LibreOffice Calc에서 열어 봤습니다

코드 열에 `00123`과 `12345678901234567890`을 넣은 CSV를 만들었습니다. [재현용 CSV 파일](/downloads/blog/csv-leading-zeros/codes.csv)을 내려받아 직접 열어 볼 수 있습니다.

2026년10월19일 LibreOffice Calc 26.2.5.2의 기본 CSV 변환으로 XLSX 파일을 만들고, 시트 XML에 저장된 셀 값을 확인했습니다. 화면 표시가 아니라 파일에 기록된 값입니다.

- CSV에 `00123`이라고 적은 값은 XLSX에서 숫자 `123`으로 저장됐습니다. 앞의 0이 없어졌습니다.
- CSV에 `12345678901234567890`이라고 적은 값은 `1.23456789012346E+019`로 저장됐습니다. 원래 값과 끝자리가 달라졌습니다.

변환은 화면을 띄우지 않는 `soffice --headless --convert-to xlsx --outdir out codes.csv` 명령으로 실행했습니다. 이는 LibreOffice Calc의 기본 변환 결과이며 대화상자에서 열 형식을 지정한 실험은 아닙니다. 셀 값과 형식은 [측정 기록](/downloads/blog/csv-leading-zeros/measurements.json)에 남겼습니다. Excel의 동작을 대신 측정한 값은 아닙니다. Microsoft는 Excel이 앞자리 0을 제거하고 15자리를 넘는 숫자를 숫자로 처리할 때 정밀도가 달라질 수 있다고 안내합니다. [Excel에서 앞자리 0과 큰 숫자 유지하기](https://support.microsoft.com/en-us/excel/keeping-leading-zeros-and-large-numbers)

LibreOffice Calc에서 직접 가져온다면 CSV 가져오기 미리 보기에서 코드 열을 선택하고 **열 형식 → 텍스트**를 고르세요. LibreOffice 도움말도 앞자리 0을 유지하려면 가져올 열을 텍스트 형식으로 지정하라고 설명합니다. [Calc의 텍스트 가져오기 안내](https://help.libreoffice.org/latest/en-GB/text/shared/00/00000208.html)

## Excel에서는 원본 CSV를 텍스트 열로 가져오세요

CSV를 열어 코드가 바뀐 것처럼 보이면 그 상태로 CSV를 저장하지 말고 닫으세요. 원본 CSV를 다시 가져온 뒤 해당 열을 텍스트로 지정합니다. 이미 저장해 원본의 값을 덮어썼다면 파일을 만든 곳에서 다시 받으세요.

1. Excel에서 빈 통합 문서를 엽니다.
2. **데이터 → 텍스트/CSV에서**를 선택하고 원본 파일을 고릅니다.
3. 미리 보기에서 **데이터 변환** 또는 **편집**을 선택해 Power Query 편집기를 엽니다.
4. 코드 열 머리글을 선택하고 **홈 → 변환 → 데이터 형식 → 텍스트**를 고릅니다.
5. 열 형식 변경 창에서 **현재 항목 바꾸기**를 선택합니다.
6. 미리 보기에서 `00123`과 긴 코드가 그대로 보이는지 확인한 뒤 **닫기 및 로드**를 선택합니다.

메뉴 이름은 Excel 버전과 언어 설정에 따라 다를 수 있습니다. 위 Microsoft 안내에서 텍스트/CSV 가져오기 뒤 열 형식을 텍스트로 바꾸는 절차를 확인할 수 있습니다.

열 전체를 텍스트로 가져오면 그 열은 계산용 숫자가 아니라 문자로 저장됩니다. 합계나 계산이 필요한 값은 별도 숫자 열로 다루세요. 코드 자릿수가 항상 같고 그 길이를 안다면 사용자 지정 숫자 형식으로 앞의 0을 화면에 다시 표시할 수 있습니다. 이는 셀의 숫자 값을 바꾸지 않으며, 원본 CSV나 다른 프로그램에 내보낸 값의 복구를 대신하지 않습니다.

## 가져온 뒤 원본과 대조하세요

코드가 있는 열은 앞자리 0뿐 아니라 긴 숫자의 끝자리도 확인하세요. 가져오기 전후의 값을 비교하고, 원본 CSV는 별도 파일로 보관합니다. 이미 변환된 파일만 남았다면 원래 값을 추측하지 말고 파일을 만든 곳에서 다시 받으세요.

한글이 깨지는 문제는 문자 저장 방식이 원인일 수 있습니다. 열이 밀리는 문제는 구분자와 따옴표가 원인일 수 있습니다. 각각 다른 문제이므로 [CSV 한글이 깨질 때](/blog/csv-korean-encoding)와 [CSV에서 열이 밀릴 때](/blog/csv-columns-and-quotes)를 참고하세요.

## 재현 방법과 범위

재현용 파일에는 `코드` 머리글과 실험용 코드 2개만 들어 있습니다. LibreOffice Calc 26.2.5.2에서 화면 없이 기본 변환으로 CSV를 XLSX로 저장했습니다. 저장된 XLSX의 시트 XML에서 셀 형식과 값을 읽어 변환 결과를 확인했습니다. 결과는 이 환경에서 한 번 실행한 관측값입니다.

Excel에서는 같은 버전과 설정을 모두 재현해 확인하지 않았습니다. Excel 관련 설명은 Microsoft 지원 문서에 근거합니다. 자동 변환 설정은 Excel 버전에 따라 달라질 수 있으므로, 가져오기 미리 보기에서 실제 값을 확인하세요.
