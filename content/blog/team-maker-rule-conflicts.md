## 다시 눌러도 해결되지 않는 배정 조건

[팀 메이커](/team-maker)에서 같은 팀·다른 팀 규칙을 추가하다 보면 팀을 만들 수 없다는 안내가 나올 수 있습니다. 조건이 서로 맞지 않으면 다시 섞어도 해결되지 않습니다.

참가자를 지우기 전에 **함께 묶인 사람 수, 서로 떨어져야 하는 사람 수, 팀 수**를 확인하세요. 이름만 따로 보면 놓치기 쉬운 충돌이 보입니다.

처음 3개 사례는 가람·나래·다온·라온·마루·바다라는 가상 참가자 6명으로 확인했습니다. 마지막 사례는 4명을 더한 10명으로 확인했습니다. 기존 명단에서 따라 한다면 먼저 현재 명단과 규칙을 보관하세요.

화면에 나온 문구에 따라 아래 항목부터 확인하세요.

| 화면 안내                                                                      | 먼저 확인할 것                                                      |
| ------------------------------------------------------------------------------ | ------------------------------------------------------------------- |
| 같은 팀 규칙과 다른 팀 규칙이 서로 충돌합니다. 규칙을 확인해 주세요.           | 같은 팀으로 이어진 사람을 다른 팀으로도 지정했는지                  |
| 서로 다른 팀으로 나눌 참가자보다 팀 수가 적습니다. 팀 수나 규칙을 고쳐 주세요. | 서로 떨어져야 할 사람 수와 전체 팀 수                               |
| 같은 팀으로 지정한 인원이 한 팀 정원(3명)보다 많습니다.                        | 가장 큰 같은 팀 묶음의 인원. 괄호 안 정원은 설정에 따라 달라집니다. |
| 현재 규칙으로 고르게 나눌 수 없습니다. 규칙이나 팀 수를 고쳐 주세요.           | 각 묶음이 들어갈 크기의 팀이 충분한지                               |

## 가람과 나래, 나래와 다온을 함께 묶으면

아래의 두 규칙을 등록했다고 가정해 보세요.

- 가람·나래: 같은 팀
- 나래·다온: 같은 팀

나래는 한 팀에만 들어갈 수 있습니다. 그래서 두 규칙은 결국 가람·나래·다온이라는 3명 묶음을 만듭니다. 처음부터 3명을 한꺼번에 선택한 것과 같은 관계입니다.

여기에 **가람·다온: 다른 팀**을 추가하면 모순이 생깁니다. 두 사람은 나래를 통해 이미 같은 팀으로 연결돼 있습니다.

| 규칙                                           | 6명을 2팀으로 나눈 결과 |
| ---------------------------------------------- | ----------------------- |
| 가람·나래 함께, 나래·다온 함께, 가람·다온 따로 | 규칙 충돌로 배정 중단   |
| 위에서 가람·다온을 따로 두는 규칙만 제거       | 3명씩 2팀으로 배정 가능 |

이때는 새 규칙을 더하지 말고 꼭 필요한 관계를 먼저 정하세요. 가람과 다온을 떨어뜨려야 한다면 함께 묶는 연결 중 하나도 수정해야 합니다. 단지 오류를 없애려고 필요한 조건을 버리지는 마세요.

참가자가 많다면 같은 팀 규칙에 한 번이라도 등장한 이름을 따라가 보세요. A·B, B·C, C·D처럼 연결되면 전체가 4명 묶음입니다.

## 다른 팀으로 지정한 사람이 팀 수보다 많을 때

이번에는 가람·나래·다온을 한 번에 선택해 **다른 팀 지정**을 했습니다. 이 규칙은 3명이 각각 다른 팀에 들어가야 한다는 뜻입니다.

2팀으로는 세 사람을 모두 떨어뜨릴 수 없습니다. 참가자 전체가 6명이라는 사실과는 관계없습니다.

| 설정                                    | 결과                | 수정 방법                                     |
| --------------------------------------- | ------------------- | --------------------------------------------- |
| 가람·나래·다온을 서로 다른 팀, 전체 2팀 | 배정 중단           | 실제로 모두 떨어져야 한다면 3팀 이상으로 변경 |
| 같은 규칙, 전체 3팀                     | 2명씩 3팀 배정 가능 | 각 팀에 세 사람 중 1명씩 있는지 확인          |

원하는 조건이 “가람만 나래·다온과 떨어지기”라면 의미가 다릅니다. 이 경우에는 가람·나래와 가람·다온을 각각 다른 팀으로 등록하세요. 나래와 다온은 같은 팀에 있어도 되므로 2팀에서 가능한 조건이 됩니다.

세 사람을 한 규칙으로 고르는 것과 두 쌍을 따로 등록하는 것은 결과가 다릅니다. 참가자를 선택하기 전에 문장으로 조건을 적어 보세요.

**팀당 인원으로 나누기**를 사용한다면 인원을 줄여 전체 팀 수를 늘릴 수 있습니다. 이 예제는 팀당 3명에서 2명으로 바꾸면 2팀이 3팀이 됩니다. 함께 묶은 사람이 있다면 그 묶음도 줄어든 정원에 들어가는지 확인하세요.

## 같은 팀 묶음이 한 팀 정원보다 클 때

6명을 2팀으로 고르게 나누면 한 팀은 3명입니다. 가람·나래·다온·라온을 같은 팀으로 묶으면 4명이라 들어갈 자리가 없습니다.

이 경우에는 같은 팀 묶음을 줄이거나 모임의 팀 구성을 바꿔야 합니다. 다른 팀 규칙을 전부 지워도 4명 묶음 자체는 그대로이므로 문제가 남습니다.

**팀 수를 늘리면 오히려 한 팀의 자리가 줄어듭니다.** 6명을 3팀으로 나누면 한 팀은 2명입니다. 함께 배정할 사람이 많다는 이유로 팀 수부터 늘리면 더 어려워질 수 있습니다.

인원이 나누어떨어지지 않을 때도 확인 방법은 같습니다. 예를 들어 10명을 3팀으로 나누면 팀별 인원은 4명·3명·3명입니다. 이 조건에서 5명을 같은 팀으로 묶을 수는 없습니다.

## 가장 큰 묶음은 들어가는데도 배정이 안 될 때

최대 정원만 맞춰도 부족할 수 있습니다. 10명을 3팀으로 나눌 때 **4명이 들어갈 팀은 1개뿐**입니다. 4명 묶음을 2개 만들면 각 묶음은 최대 정원 이내여도 동시에 배정할 수 없습니다.

앞의 6명에 사라·아라·자람·하람을 추가했습니다. 가람·나래·다온·라온을 첫 묶음으로, 마루·바다·사라·아라를 두 번째 묶음으로 지정했습니다. 다른 팀 규칙은 넣지 않았습니다.

| 같은 팀으로 지정한 묶음       | 10명을 3팀으로 나눈 결과                     |
| ----------------------------- | -------------------------------------------- |
| 4명 묶음 2개                  | “현재 규칙으로 고르게 나눌 수 없습니다” 안내 |
| 첫 묶음 4명, 두 번째 묶음 3명 | 4명·3명·3명으로 배정 가능                    |

두 번째 묶음에서 아라를 빼자 배정됐습니다. 함께 있어야 할 조건을 유지해야 한다면 모임의 팀 수를 다시 정하세요. 이 예제는 10명을 2팀으로 나누면 각 5명이라 4명 묶음 2개가 각각 들어갈 수 있습니다.

이 안내가 항상 같은 원인을 뜻하지는 않습니다. 여러 규칙이 얽힌 경우도 있으므로, 묶음 크기뿐 아니라 **그 크기를 받아 줄 팀이 몇 개인지**부터 확인하세요.

## 현장에서 확인할 순서

1. 이번 배정에 포함된 참가자 수와 팀 수를 확인하세요. 불참자를 제외했다면 정원도 다시 계산하세요.
2. 같은 팀 규칙을 연결해 묶음별 인원을 세세요. 각 묶음이 들어갈 크기의 팀이 충분한지도 확인하세요.
3. 그 묶음 안에 다른 팀 규칙이 들어 있는지 확인하세요.
4. 서로 다른 팀으로 지정한 인원이 팀 수를 넘는지 확인하세요.
5. 마지막에 추가한 규칙부터 하나씩 수정하고 다시 배정하세요.

배정에 성공하면 팀별 인원과 꼭 필요한 규칙을 결과에서 다시 확인하세요. 인원수가 비슷하다고 경기 실력이나 업무량까지 비슷한 것은 아닙니다. 이 도구는 입력한 배정 규칙과 인원 균형을 처리합니다.

## 실제 함수로 확인한 범위

2026년 10월 13일에 사이트가 사용하는 `makeTeams` 함수에 위의 실패 사례 4개와 수정 사례 4개를 넣었습니다. 수정 사례는 참가자 누락·중복, 팀별 인원 차이, 규칙 준수 여부를 검사했습니다. [입력 규칙과 전체 결과](/downloads/blog/team-rule-conflicts/measurements.json)를 볼 수 있습니다.

기록에 남기는 결과를 일정하게 만들기 위해 실험에서는 섞는 값을 고정했습니다. 실제 화면에서는 팀 번호와 나머지 조합이 달라질 수 있습니다. 이 검사는 모든 조합의 등장 확률을 측정한 실험은 아닙니다.

복잡한 규칙 여러 개가 얽히면 위 항목만으로 원인을 찾기 어려울 수 있습니다. 꼭 필요한 조건부터 남기고 하나씩 다시 추가하세요. 기본 입력과 명단 보관은 [팀 메이커 사용 방법](/blog/team-maker-introduction)에서 확인할 수 있습니다.
