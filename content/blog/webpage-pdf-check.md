## 마지막 쪽이 거의 비어 있어도 먼저 읽어보세요

웹페이지를 PDF로 보관할 때 첫 쪽만 보고 저장을 끝내기 쉽습니다. 하지만 긴 글에서는 마지막 문단이나 표의 오른쪽이 빠지지 않았는지도 확인해야 합니다.

이 블로그의 [대진표 결과 수정 글](/blog/bracket-result-correction)을 실제 운영 주소에서 열어 PDF로 저장했습니다. A4 세로, 배율100%, 사방 여백12mm로 출력하니5쪽이 됐습니다. 마지막 쪽에는 짧은 안내와 링크, 사이트 하단 정보가 남았습니다.

이번에는 광고·통계 요청을 차단했습니다. 직접 저장할 때 광고가 표시되거나 인쇄 설정이 다르면 배치와 쪽 수가 달라질 수 있습니다.5쪽을 모든 환경의 기준으로 삼지는 마세요.

![PDF의5쪽 위쪽에 브라우저 저장 안내와 도구 링크가 남아 있는 모습](/images/blog/webpage-pdf/last-page.png '실제 PDF의5쪽 윗부분입니다. 아래의 넓은 빈 공간은 잘라냈습니다. 브라우저 인쇄창을 찍은 화면은 아닙니다.')

휴대전화에서 그림 속 문장이 작다면 [원본 그림](/images/blog/webpage-pdf/last-page.png)을 열어 확대하세요.

여백이 많다는 이유만으로5쪽을 빼면 **브라우저 저장 기록이 보이지 않을 때 읽을 안내**도 함께 빠집니다. 필요한 범위를 읽고 결정해야 합니다. 이 글의 PDF는 모든 쪽을 그대로 남겼습니다.

이 출력은 브라우저 자동 조작 도구인 Playwright로 Chromium을 실행해 만들었습니다. Chrome 인쇄창을 직접 누르거나 종이로 출력한 결과는 아닙니다. 아래의 수동 저장 절차와 자동 출력의 확인 결과를 구분해 적었습니다.

## PC에서 PDF 사본을 만드는 순서

Chrome에서는 다음 순서로 시작하세요. 스마트폰의 인쇄 메뉴는 이 안내의 대상이 아닙니다.

1. 보관할 **글 본문 주소**를 여세요. 목록 화면을 저장하면 글 전체가 들어가지 않습니다.
2. 그림이 표시되는지 확인하세요. 필요한 내용이 접혀 있다면 먼저 펼치세요.
3. Windows·Linux에서는 `Ctrl+P`, Mac에서는 `⌘+P`를 누르세요.
4. 인쇄 대상에서 **PDF로 저장**을 선택하세요. 처음에는 페이지 범위를 **전체**로 두세요.
5. 미리보기에서 첫 쪽부터 마지막 쪽까지 확인한 뒤 저장하세요. 기존 파일을 덮어쓰지 않도록 새 이름을 붙이세요.

직접 저장한다면 `2026-10-28-bracket-guide.pdf`처럼 **저장한 날**을 붙일 수 있습니다. 이 글에서 제공하는 예제 파일 이름은 `bracket-webpage.pdf`입니다. 원문이 나중에 수정돼도 이 파일이 저절로 갱신되지는 않습니다. 파일명의 날짜는 원문의 게시일과 다를 수 있습니다.

단축키와 인쇄 대상 선택은 [Chrome 공식 인쇄 도움말](https://support.google.com/chrome/answer/1069693?hl=ko&co=GENIE.Platform%3DDesktop)을 확인했습니다. 메뉴 이름과 설정 위치는 버전에 따라 달라질 수 있습니다.

## 미리보기에서는 표와 그림이 있는 쪽을 먼저 살펴보세요

글자만 있는 첫 쪽이 괜찮아도 중간의 표나 그림은 잘릴 수 있습니다. 이번 PDF에서는3쪽의 ‘고치기 전·고친 뒤’ 표3행과 대진표 그림을 확인했습니다. 표의 오른쪽 열과 그림은 보였고, 글자와 겹치지 않았습니다.1~5쪽을 이미지로 바꿔 모든 쪽을 확인했습니다.

직접 저장할 때는 다음 부분을 눈으로 살펴보세요.

- 표의 맨 오른쪽 제목과 값이 모두 보이는지
- 그림의 끝과 설명 문장이 빠지지 않았는지
- 쪽이 바뀌는 곳에서 문장이 이어지는지
- 마지막 쪽에 본문이나 꼭 필요한 링크가 남아 있는지

오른쪽이 잘리면 인쇄 설정에서 가로 방향이나 배율 항목을 찾아 조정해보세요. 이 설정의 메뉴 위치와 조정 뒤 결과는 이번에 직접 확인하지 않았습니다. 배율을 낮춘 뒤에는 글자가 너무 작아지지 않았는지 다시 확인하세요. 여백·용지·배율을 바꾸면 쪽 수도 달라질 수 있으므로 페이지 범위를 이전 숫자로 고정하지 마세요.

화면과 PDF의 배치가 다른 것만으로 저장 실패는 아닙니다. 사이트는 종이나 PDF에 출력할 때 별도 모양을 적용할 수 있습니다. [MDN의 인쇄용 스타일 설명](https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Media_queries/Printing)에서도 화면과 인쇄에 서로 다른 배치를 지정하는 방법을 안내합니다. 방문자는 미리보기에서 필요한 내용이 남았는지를 기준으로 판단하세요.

## 저장한 파일을 다시 열고 링크의 목적을 구분하세요

인쇄창을 닫은 뒤에는 **실제로 저장된 PDF**를 다시 여세요. 미리보기만 확인하고 파일이 생겼다고 생각하지 마세요.

이번 파일은 PDF를 읽는 도구인 pypdf로 확인했습니다.3쪽에는 대진표 원본 그림을 여는 웹주소가 남았고,5쪽에는 브라우저에 저장한 내용이 사라졌을 때의 안내 글 주소가 남았습니다. 단, 주소가 파일에 들어 있다는 사실과 모든 PDF 뷰어에서 클릭이 된다는 것은 다릅니다. 공유할 때 쓸 뷰어에서 필요한 링크를 직접 눌러 확인하세요.

또한 **링크가 남는 것과 연결된 자료까지 PDF 안에 들어가는 것은 다릅니다.** 이번 PDF에는 본문의 그림이 보이지만, ‘원본 이미지’ 링크는 별도 웹주소를 가리킵니다. 인터넷이 없는 곳에서도 그 원본을 봐야 한다면 따로 저장하고 열리는지 확인하세요.

머리글·바닥글을 끈 이번 출력에는 글을 저장한 원문 주소가 종이 위에 별도로 표시되지 않았습니다. 파일과 함께 원문 주소와 저장일을 메모해두세요.

```text
원문: https://hjh3311504.github.io/blog/bracket-result-correction
저장일: 2026-10-28 (한국 시간)
```

PDF는 저장 당시 읽을 수 있던 내용의 사본입니다. 웹페이지의 버튼과 입력 기능까지 계속 사용할 수 있는 사본으로 기대하지 마세요. 도구로 다시 작업하려면 원래 웹페이지를 여세요. 일반 웹페이지 저장은 [Chrome의 오프라인 페이지 안내](https://support.google.com/chrome/answer/7343019?hl=ko&co=GENIE.Platform%3DDesktop)에서 별도로 설명합니다.

## 이번 사본으로 확인할 수 있는 것

[실제 출력한5쪽 PDF](/downloads/blog/webpage-pdf/bracket-webpage.pdf)를 열어3쪽의 표와 그림,5쪽의 안내를 확인할 수 있습니다. 글자가 검색되지 않는 파일을 받았다면 [PDF 검색 문제 안내](/blog/pdf-text-search-troubleshooting)를 참고하세요. 이번 글은 검색 가능 여부보다 **보관할 내용과 연결 자료가 빠지지 않았는지**에 초점을 맞췄습니다.

2026년10월28일에 macOS arm64·Chromium151.0.7922.34에서 확인했습니다. 출력 설정은 다음과 같습니다.

- 밝은 테마, A4 세로
- 사방 여백12mm, 배율100%
- 배경 그래픽과 머리글·바닥글 끔

사이트 본문이나 스타일은 바꾸지 않았으며 광고·통계 등 다른 도메인으로 가는 요청은 차단했습니다. 다른 브라우저·스마트폰·종이 출력은 확인하지 않았습니다.

[출력 설정과 확인 기록](/downloads/blog/webpage-pdf/verification.json)에 파일 크기·해시·쪽별 링크를 남겼습니다. 해시는 파일 내용이 같은지 비교하는 값입니다. [파일 해시 비교 안내](/blog/file-hash-comparison)에서 사용법을 볼 수 있습니다.

개발 환경에서 다시 만들려면 저장소의 npm 의존성과 Playwright Chromium을 설치한 뒤 `node scripts/export_blog_page_pdf.js`를 실행하세요. [재현 스크립트](https://github.com/hjh3311504/hjh3311504.github.io/blob/main/scripts/export_blog_page_pdf.js)는 `output/pdf/`에 PDF와 출력 설정·해시를 저장합니다. 쪽별 링크와 눈으로 확인한 결과는 별도로 기록한 것이며 자동 생성되지 않습니다. 원문이나 브라우저 버전이 바뀌면 배치와 쪽 수도 달라질 수 있습니다. 출력 방식은 [Playwright의 PDF 문서](https://playwright.dev/docs/api/class-page#page-pdf)를 따릅니다.
